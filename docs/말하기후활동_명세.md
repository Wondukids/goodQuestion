정본 문서. 배경은 0절, 확정 결정은 1절, 용어는 2절.

⛔ **이 명세는 미션1(배 따기)·미션2(친구 고민)를 건드리지 않는다.** 그 둘의 정본은

📌 이 명세는 **보호자 리포트가 만들어지는 시점을 옮긴다** (F10). 그 부분은

## 0. 배경 — 지금 무엇이 비어 있나

아이가 이야기를 다 보고 나면 하는 활동이 하나 더 있다. 카드 넉 장을 이야기 순서대로
놓고(1단계), 맞춘 카드와 「핵심 단어」를 보면서 줄거리를 통째로 들려주는(2단계) 활동이다.
화면은 이미 다 만들어져 있다 — `src/stories/fart-bride/minigame/finale.tsx`.

비어 있는 것은 **그 화면이 아무 데도 연결되어 있지 않다**는 것이다.

| 조각 | 지금 |
|---|---|
| 활동 화면(순서 맞추기 + 녹음) | **있다** — 다만 개발용 `/dev/minigame` 에서만 열린다 |
| 이야기 끝 화면에서 들어가는 길 | 없다 (`play.tsx` 끝 화면 버튼은 「다시 보기」·「이야기 소개로」 둘뿐) |
| 결과 표 `post_activity_results` | **표는 이미 서 있다** (`sql/001_schema.sql` 9번) — 다섯 칸이 전부 빈 채로 |
| 이야기별 카드·단어를 담을 칸 `stories.post_activity_config` | 칸만 있고 비어 있다 |
| 필수 단어 12개 (4장면 × 3개) | 코드 상수에 박혀 있다 (`finale-script.ts`) |
| 받아쓴 줄거리를 **읽고 판단하는 일** | 없다 — `finale.tsx:510` 주석이 «리포트로 보낼 자리다 (아직 연결 전)» 이라고만 적혀 있다 |
| 보호자 리포트와의 연결 | 없다 — 리포트 명세에 후활동이 한 줄도 없다 |

이 명세가 정하는 것은 위 일곱 줄을 잇는 **서버 계약·LLM 판정 규칙·리포트 시점**이다.

| **F18** | **`is_order_correct` 의 뜻은 「끝내 맞췄나」** — 이름은 그대로 두고 문서·주석에 못박는다 | 팀 DB 에 이미 서 있는 칸이라 이름을 바꾸면 마이그레이션이 하나 더 든다. 이 칸이 있어야 「순서를 못 맞추고 나갔다」를 구별한다 |

### 이 명세가 정한 것 (인터뷰 밖 — 뒤집어도 되는 판단)

- **순서 채점은 앱이 하고, 서버는 받은 순서를 스스로 다시 대조한다** (5.B). 정답 순서는
  아이가 방금 본 이야기라 감출 값이 아니다. 앱이 채점하면 서버가 죽어도 활동이 끝까지
  돌아가고 왕복도 준다.
- **리포트 서술(LLM이 쓰는 문장) 프롬프트는 건드리지 않는다** (10절 비스코프). 숫자에만
  싣는다. 서술 프롬프트를 고치면 골든셋과 검사가 함께 흔들린다.

## 2. 용어

| 말 | 뜻 |
|---|---|
| **후활동** | 이야기를 다 본 뒤의 「말하기 후 활동」. 순서 맞추기 → 줄거리 말하기 두 단계 |
| **카드** | 장면 그림 한 장 (넉 장). 순서 맞추기의 말이자, 말하기 단계의 힌트 |
| **필수 단어(핵심 단어)** | 줄거리를 말할 때 나오면 좋은 단어. 카드 한 장에 셋씩 총 12개 |
| **판정 3단계** | `used` 그대로 씀 · `similar` 비슷한 말로 씀 · `missing` 안 씀 |
| **근거 인용** | 그렇게 판정한 까닭이 되는 **아이 말 원문 조각**. 지어낸 문장이면 버린다 (6절) |
| **제출** | 순서 맞추기에서 「다 놓았어요!」를 누른 것. 틀려서 다시 놓아도 한 번으로 센다 |

| | 미션 1·2 | 후활동 |

## 4. 데이터 모델

### 4.1 채우는 칸 — `stories.post_activity_config` (F1)

```json
{
  "cards": [
    { "id": "endure", "title": "방귀를 참는 며느리", "keywords": ["시집", "참다", "걱정"] },
    { "id": "burst",  "title": "들켜버린 큰 방귀",   "keywords": ["방귀", "깜짝", "기둥"] },
    { "id": "pear",   "title": "배나무 앞 방귀 대작전", "keywords": ["배나무", "힘껏", "우수수"] },
    { "id": "pride",  "title": "마을의 자랑이 된 며느리", "keywords": ["당당하다", "칭찬", "고마워"] }
  ],
  "answer_order": ["endure", "burst", "pear", "pride"],
  "tray_order":   ["pear", "pride", "endure", "burst"]
}
```

- `cards` 의 차례가 정답 순서지만, 읽는 쪽이 헷갈리지 않게 `answer_order` 를 따로 적는다.
- `tray_order` 는 처음 트레이에 깔리는 (섞인) 순서다. 정답과 같으면 안 된다.
- ⛔ **그림 파일·칩 색은 넣지 않는다.** 그건 시안에서 나온 앱 자산이라 `id` 로 앱이 잇는다.

⚠️ **시드 주의.** `src/llm/db/seed.ts` 는 `stories` 만 `onConflictDoNothing` 이다 (결정 4 · 4차).
이미 서 있는 이야기 행에는 시드를 다시 돌려도 이 칸이 **안 들어간다.** 그래서 값은
마이그레이션(4.4)의 `UPDATE` 로 넣고, `seed.ts` 의 이야기 정의에도 같은 값을 나란히 둔다.

### 4.2 이미 있는 표 — `post_activity_results` 의 칸 뜻 확정 + 두 칸 추가

```sql
-- 이미 서 있는 칸 (sql/001_schema.sql 9번) — 뜻을 여기서 못박는다
-- submitted_order  text[]      아이의 **첫 제출** 순서 (틀렸어도 그대로). F7
-- is_order_correct boolean     🔴 **끝내 맞췄나.** 못 맞추고 나갔으면 false. F18
--                              ⚠️ 「첫 제출이 정답이었나」가 아니다. 그건 attempt_count=1 로 안다
-- attempt_count    smallint    「다 놓았어요!」를 누른 횟수 (통과한 회차 포함)
-- retelling_text   text        서버가 받아쓴 아이 줄거리 원문
-- completed_at     timestamptz 「마치기」를 누른 시각. 중간에 나갔으면 NULL

ALTER TABLE post_activity_results ADD COLUMN analyzed_at      timestamptz;
ALTER TABLE post_activity_results ADD COLUMN analysis_version varchar;
```

- `analyzed_at` 이 NULL = **판정을 못 했다** (LLM 실패·아직 안 말함). 「단어를 하나도 안 썼다」와
  구별된다 — 그쪽은 `analyzed_at` 이 차고 `post_activity_keywords` 가 전부 `missing` 이다.
- `analysis_version` 은 어느 판 프롬프트가 낸 결과인가 (`'retelling_v1'` 로 시작).

### 4.3 새 표 — `post_activity_keywords` (F3)

```sql
CREATE TABLE post_activity_keywords (
    id         uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
    result_id  uuid        NOT NULL REFERENCES post_activity_results (id) ON DELETE CASCADE,
    -- 어느 카드(장면)의 단어인가. post_activity_config.cards[].id 값
    card_id    varchar     NOT NULL,
    word       varchar     NOT NULL,
    status     varchar     NOT NULL CHECK (status IN ('used', 'similar', 'missing')),
    -- 그렇게 본 근거 — 아이 말 원문에서 떼어 온 조각. missing 이면 NULL (6절 ③)
    evidence   text,
    -- 'rule' 규칙이 글자로 찾음 · 'llm' 판정 LLM 이 비슷한 말로 봄 (6절 ①②)
    decided_by varchar     NOT NULL CHECK (decided_by IN ('rule', 'llm')),
    created_at timestamptz NOT NULL DEFAULT now(),
    UNIQUE (result_id, card_id, word)
);
CREATE INDEX idx_post_activity_keywords_word ON post_activity_keywords (word);
```

- **판정한 단어는 12개 전부 행이 생긴다** — `missing` 도 행으로 남는다. 「없는 것」을 세려면
  행이 있어야 한다.
- 다시 판정하면 그 `result_id` 의 행을 **모두 지우고 다시 넣는다.**

### 4.4 마이그레이션 — `sql/007_post_activity.sql`

### 4.5 세션 상태 — 건드리지 않는다 (F10)

마지막 장면이 끝나면 **지금처럼 곧바로 `completed`** 다 (`src/llm/repo/sessions.ts:566`).
`post_activity` 상태는 여전히 안 쓴다.

후활동은 「끝난 세션에도 결과를 받는」 활동이 된다. `post_activity_results` 는 세션 번호로만
걸려 있어 상태와 무관하므로 표를 바꿀 것이 없다.

## 5. API 계약 — 아이 앱 봉투 그대로

응답은 `{ ok: true, data }` / `{ ok: false, error }` (`src/session/controller/envelope.ts`).
라우트 파일은 한 줄 재-내보내기, 로직은 `src/session/controller/post-activity.ts` 에 둔다.

### A. `GET /api/sessions/{sid}/post-activity` — 활동 열기

```json
{
  "config": { "cards": [ … ], "answer_order": [ … ], "tray_order": [ … ] },
  "result": {
    "submitted_order": null, "is_order_correct": null, "attempt_count": 0,
    "retelling_text": null, "completed_at": null
  }
}
```

- `result` 는 이미 저장된 것이 있으면 그대로 준다 — 아이가 중간에 나갔다 돌아온 경우다.
- 이 이야기에 `post_activity_config` 가 없으면 404 `POST_ACTIVITY_NOT_CONFIGURED`.
  앱은 그때 후활동 버튼을 **아예 그리지 않는다** (그 이야기는 F13 으로 돈다).

### B. `POST /api/sessions/{sid}/post-activity/order` — 순서 제출 (누를 때마다)

요청 `{ "submitted_order": ["pear", "endure", "burst", "pride"] }`
응답 `{ "is_correct": false, "attempt_count": 1 }`

- 서버가 `answer_order` 와 대조해 `is_correct` 를 **스스로 계산한다** (앱 값은 받지 않는다).
- `submitted_order` 칸은 **첫 호출에만 쓴다** — 이미 값이 있으면 덮지 않는다 (F7).
- 호출마다 `attempt_count += 1`. 맞았으면 `is_order_correct = true` (F18).
- 행이 없으면 이때 만든다 (F8 — 순서 단계가 곧 첫 저장 시점).

### C. `POST /api/sessions/{sid}/post-activity/retelling` — 녹음 보내기 (F6)

요청: `multipart/form-data` — `audio`(녹음 blob) · `channels`. 대화 턴 API 와 같은 모양.

```json
{
  "text": "며느리가 시집와서 방귀를 참았는데…",
  "analyzed": true,
  "keywords": [
    { "card_id": "endure", "word": "시집", "status": "used",    "evidence": "시집와서",           "decided_by": "rule" },
    { "card_id": "endure", "word": "참다", "status": "similar", "evidence": "방귀를 꾹 눌렀어요", "decided_by": "llm" },
    { "card_id": "endure", "word": "걱정", "status": "missing", "evidence": null,                 "decided_by": "llm" }
  ]
}
```

- 아무 말도 안 담겼으면 `{ "empty": true }` — 아무것도 저장하지 않는다.
- **받아쓰기가 되면 `retelling_text` 를 무조건 먼저 저장한다.** 그다음 판정을 돌린다.
- LLM 판정이 실패하면 `{ "text": …, "analyzed": false, "keywords": null }` 로 **200 을 준다** (F8).
- 녹음 길이 한도는 지금 화면 그대로 55초 (`MAX_TELL_SEC`).

### D. `POST /api/sessions/{sid}/post-activity/complete` — 활동 종료 (⭐ 리포트를 띄운다)

요청 `{ "reason": "finished" | "left" }` · 응답 `{ "report": "queued" | "exists" }`

| `reason` | 언제 앱이 부르나 | `completed_at` |
|---|---|---|
| `finished` | 「마치기」를 눌렀다 | 채운다 |
| `left` | 활동을 안 하고 끝 화면을 떠났다 (다시 보기 · 이야기 소개로 · 뒤로가기) | NULL 로 둔다 |

- **둘 다 리포트를 띄운다** (F11) — `queueReport(session_id)`, 기다리지 않는다.
- **반복 호출은 안전하다.** 리포트 행이 이미 있으면 만들지 않고 돌아간다 (기존 `queueReport`
  규칙 그대로). 아이가 마치고 나서 끝 화면을 떠나면 이 API 가 두 번 불리는데, 두 번째는
  아무 일도 일어나지 않는다.
- 세션 상태는 **건드리지 않는다** — 이미 `completed` 다 (F10).

### E. 오류 코드

| 코드 | HTTP | 언제 |
|---|---|---|
| `POST_ACTIVITY_NOT_CONFIGURED` | 404 | 이 이야기에 후활동 설정이 없다 |
| `POST_ACTIVITY_NOT_ALLOWED` | 409 | 세션이 아직 `completed` 가 아니다 (이야기가 안 끝났다) |
| `SESSION_NOT_FOUND` | 404 | 기존과 같다 |
| `STT_FAILED` | 502 | 받아쓰기 실패. **재시도 가능**(`retryable: true`) |

⚠️ LLM 판정 실패는 오류가 아니다 — 5.C 처럼 200 에 `analyzed: false` 로 싣는다.

## 6. LLM 재료와 경계 — `prompts/retelling_keywords` 신설

프롬프트 폴더는 관례대로 두 파일: `보낼것.md`(실제로 보내는 본문) · `해설.md`(왜 이렇게 썼나).

### 6.1 판정은 3단이다 — LLM 은 가운데만 맡는다

**① 규칙이 먼저 거른다.** 이미 있는 낱말 대조기를 쓴다 —
`src/report/engine/verify.ts` 의 `낱말이_발화에_있나()`. 글자로 찾히면 `status = 'used'`,
`decided_by = 'rule'` 로 끝내고 **LLM 에게 묻지 않는다.**

> 🔴 **두 글자 바닥 (F14).** 그 함수는 「~다」로 끝나는 낱말의 어간을 떼어 찾는데,
> **두 글자 낱말은 어간이 한 글자**가 된다 (「참다」→「참」). 한 글자는 「참새」·「진짜 참」
> 에도 걸려 곧바로 오판정이다. 후활동 판정에서는 **두 글자 미만 조각을 쓰지 않는다.**
> 그렇게 아무 조각도 못 만든 낱말은 규칙을 건너뛰고 곧장 ②로 간다.
> ⚠️ 원래 함수를 고치지 않는다 — 그 함수는 리포트의 낱말 세기가 쓰고 있고, 거기서는
> 지금 동작이 맞다. 후활동 쪽에서 **바닥을 걸어 부른다.**

**② 남은 단어만 LLM 에게 묻는다.** 「비슷한 말로 말했나」 하나만 판단한다.

보내는 재료(user): 이야기 제목과 한 줄 요지 · 카드 넉 장의 제목(아이가 본 순서) ·
**판정할 단어 목록**(①이 거르고 남은 것만, 단어마다 6.4의 예시를 붙여) · 아이가 말한 줄거리 원문.

받는 것:
```json
{ "words": [ { "word": "참다", "similar": true, "evidence": "방귀를 꾹 눌렀어요" } ] }
```

**③ 근거를 원문과 대조한다.** `evidence` 가 아이 원문에 실제로 없으면 **그 판정을 버리고
`missing` 으로 떨어뜨린다.** 리포트의 인용 검증(`src/report/engine/verify.ts`)과 같은 결이다.

### 6.2 지켜야 할 것 (프롬프트 본문에 못박는다)

- 아이 말을 **고쳐 쓰지 않는다.** `evidence` 는 원문에서 떼어 온 조각 그대로다.
- 없는 말을 만들지 않는다. 애매하면 `similar: false` — **의심스러우면 안 쓴 것으로 본다.**
- 점수·칭찬·조언을 쓰지 않는다. 그건 보호자 리포트 몫이다.
- 이야기 줄거리를 판단하지 않는다. 이번 판정은 **단어 12개**에 대한 것뿐이다.

### 6.3 비용

활동 한 건에 LLM 호출 **한 번**. 재료도 짧다. 규칙이 먼저 거르므로 아이가 단어를 잘
썼을수록 물어볼 것이 줄어든다.

### 6.4 단어별 통과·탈락 예시 (F17) — 2026-08-15 확정

**사람 확인을 받았다.** 이 표가 그대로 `prompts/retelling_keywords/보낼것.md` 에 들어간다.
「비슷한 말」의 경계는 여기서만 정한다 — 코드에는 두지 않는다.

| 카드 | 단어 | 통과 (`similar`) | 탈락 (`missing`) | 경계 |
|---|---|---|---|---|
| 참는 며느리 | 시집 | "결혼해서 왔어요", "새색시로 왔어요" | "집에 있었어요" | **온 것**이 드러나야 한다 |
| | 참다 | "참았어요", "꾹 눌렀어요", "안 뀌려고 했어요" | "참새를 봤어요", "참 재밌었어요" | 방귀를 **누른** 뜻이라야 한다 |
| | 걱정 | "어쩌지 했어요", "마음이 불안했어요" | "무서웠어요"<sup>†</sup>, "슬펐어요" | 앞일을 **염려**하는 마음 |
| 큰 방귀 | 방귀 | "뿡 했어요", "뽕 뀌었어요" | "냄새가 났어요" | 소리·행위를 가리켜야 한다 |
| | 깜짝 | "너무 놀랐어요", "화들짝 했어요" | "웃었어요", "시끄러웠어요" | **놀람**이 있어야 한다 |
| | 기둥 | "나무 기둥을 잡았어요", "집 기둥이 흔들렸어요" | "집이 흔들렸어요" | 기둥이라는 **물건**이 나와야 한다 |
| 배나무 | 배나무 | "배가 열린 나무", "배 나무" | "나무 앞에서" | **배**가 함께 나와야 한다 |
| | 힘껏 | "세게", "있는 힘을 다해", "빵빵하게" | "조금", "살짝" | **세기**가 크다는 말 |
| | 우수수 | "후두둑 떨어졌어요", "막 떨어졌어요", "다 떨어졌어요" | "떨어졌어요" | **많이·한꺼번에**가 드러나야 한다 |
| 자랑 | 당당하다 | "자신 있게", "부끄러워하지 않고", "떳떳하게" | "좋아했어요", "웃었어요" | **부끄러워하지 않음**이 핵심 |
| | 칭찬 | "잘했다고 했어요", "최고라고 했어요" | "좋아했어요" | **말로 높여 준** 것 |
| | 고마워 | "고맙다고 했어요", "감사하다고 했어요" | "미안하다고 했어요" | **감사**를 말한 것 |

<sup>†</sup> 🔴 **「무서웠어요」는 탈락이다** (2026-08-15 사람 확정). 걱정은 앞일을 염려하는
것이고 무서움은 지금 겁나는 것이라 감정이 다르다. 어린이 눈높이에서 붙여 볼 수도 있었지만
가르는 쪽으로 정했다 — 프롬프트에 **탈락 예시로 명시**한다.

## 7. 리포트 연결 (F9~F16)

### 7.1 언제 만드나

```
마지막 장면 끝  →  세션 completed          (지금 그대로. 리포트는 아직 안 만든다)
      │
      ├─ 아이가 후활동을 한다 ─→ 「마치기」  →  complete(reason=finished) ─┐
      ├─ 활동을 건너뛰고 나간다 ───────────→  complete(reason=left)     ─┤
      │                                                                  ├─→ queueReport()
      └─ 앱을 그냥 꺼버린다 ────→ (신호 없음) → 보호자가 리포트를 열 때 ─┘   (F11·F12)
```

- 후활동 설정이 없는 이야기는 이 그림을 타지 않는다 — **세션이 끝나는 자리에서** 지금처럼
  만든다 (F13).
- `queueReport()` 의 «리포트 행이 이미 있으면 돌아간다» 규칙은 그대로 쓴다. 세 길 중 둘이
  겹쳐 들어와도 두 번 만들지 않는다.
- ⚠️ **기존 `queueReport()` 호출 두 자리를 고친다** — `src/llm/service/run.ts:318` ·
  `src/llm/service/story.ts:228` (2026-08-15 `#38` 머지로 `api_team` 에 이미 들어와 있다).
  거기 그대로 두면 이야기가 끝나는 순간 리포트가 만들어져 후활동 결과가 못 들어간다.
  **지우지 말고 조건을 건다** — 그 이야기에 `post_activity_config` 가 **없을 때만** 부른다.
  그게 F13 의 길이다.

### 7.2 지표에 붙는 모양 (F15·F16)

`ReportMetrics` 에 한 덩이를 더한다. **기존 `counts`·`words`·`axes` 는 건드리지 않는다** (F15).

```ts
post_activity: {
  order: { correct: boolean; attempts: number; first_submission: string[] }
  /** 순서만 하고 나갔으면 null — 카드에 순서 줄만 보인다 (F16) */
  retelling: {
    analyzed: boolean          // false 면 판정을 못 했다 — 화면은 「담지 못했어요」
    text: string
    used: number; similar: number; missing: number
    words: { card_id: string; word: string; status: 'used'|'similar'|'missing'; evidence: string | null }[]
  } | null
} | null                        // 활동을 아예 안 했으면 null — 카드를 그리지 않는다
```

### 7.3 화면 (F16)

「말하기 분석」 탭에 카드 하나. 위에 순서 한 줄(«순서를 두 번 만에 맞췄어요»),
아래에 **단어 12개를 칩으로** — 쓴 것 · 비슷하게 말한 것 · 안 나온 것이 색으로 갈린다.
`retelling` 이 `null` 이면 순서 줄만 두고 «줄거리는 아직 들려주지 않았어요» 라고 적는다.

⛔ 리포트 **서술** 프롬프트(`report_analysis`·`report_guide`)는 이번에 건드리지 않는다.

## 9. 수용 기준

1. 이야기를 끝까지 보면 끝 화면에 「이야기 순서 맞추기」 버튼이 있고, 누르면 활동이 열린다.
2. 카드 제목·필수 단어가 **DB 값**으로 그려진다 — `post_activity_config` 를 고치면 화면이 바뀐다.
3. 순서를 두 번 틀리고 세 번째에 맞추면: `submitted_order` = **첫 번째** 순서,
   `attempt_count` = 3, `is_order_correct` = true.
4. 순서만 맞추고 팝업을 닫으면 그 행이 남아 있고 `retelling_text` 는 NULL 이다.
5. 줄거리를 말하면 `retelling_text` 가 차고 `post_activity_keywords` 에 **12행**이 생긴다.
6. 「시집」을 「시집와서」로 말하면 `status='used'`, `decided_by='rule'` (LLM 호출 없이).
7. **「참다」를 「참새를 봤어요」로만 말하면 `used` 가 되지 않는다** (F14 — 두 글자 바닥).
8. 「참다」를 「꾹 눌렀어요」로 말하면 `status='similar'`, `decided_by='llm'`, `evidence` 가
   아이 원문 안에 실제로 있는 조각이다.
9. LLM 이 원문에 없는 `evidence` 를 내면 그 단어는 `missing` 이 된다.
10. LLM 을 죽여 놓고 돌려도: 200 · `analyzed: false` · `retelling_text` 는 저장됨 ·
    `analyzed_at` 은 NULL · 화면은 끝까지 진행된다.
11. 「마치기」를 누르면 리포트가 만들어지고, 그 `metrics.post_activity` 에 단어 12개가 실린다.
12. **활동을 안 하고 끝 화면을 떠나도 리포트가 만들어진다** — `post_activity` 는 `null`.
13. **아무 신호 없이 앱을 꺼도**, 보호자가 리포트를 열면 그 자리에서 만들어진다 (F12).
14. 이야기가 끝난 것만으로는 리포트가 만들어지지 **않는다** (후활동이 있는 이야기에서).
15. 기존 지표(`counts.child_utterances`·`words`)는 후활동을 해도 값이 변하지 않는다 (F15).

## 11. 비스코프 · 남은 위험

**비스코프**
- 리포트 **서술**(LLM 문장) 프롬프트 변경 — 숫자에만 싣는다.
- 순서를 못 맞춘 아이를 돕는 힌트·재시도 설계 — F4 로 «기록만»이 정해졌다.
- 후활동을 여러 번 다시 하기 — 세션당 한 건이고 다시 하면 덮는다.
- 이야기 소개 화면에서 후활동만 다시 열기 — 필요해지면 별도 이슈.
- 미션 1·2 관련 어떤 변경도 하지 않는다.

**위험**
- 🔴 **두 번째 후활동은 리포트에 안 들어간다.** 「다시 보기」로 이야기를 다시 본 뒤 후활동을
  또 하면, 리포트 행이 이미 있어 다시 만들지 않는다. 결과는 표에 덮여 저장되지만 리포트는
  옛 값이다. 보호자가 「다시 만들기」를 누르면 맞춰진다 — 그 이상은 이번 범위 밖으로 둔다.
- 🟠 **보호자의 첫 열람이 느려질 수 있다** (F12 로 만들어지는 경우). 리포트 화면에
  「만드는 중」 상태가 필요하다 — `#39` 화면 갈래와 맞물린다.
