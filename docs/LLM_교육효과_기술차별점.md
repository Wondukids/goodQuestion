# 좋은질문(goodQuestion) — LLM이 아이에게 주는 좋은 영향과 기술적 차별점

## 1. LLM이 아이에게 주는 좋은 영향

### 스스로 생각을 꺼내게 하는 대화 설계
- 캐릭터는 **절대 아이 대신 답을 말하지 않는다.** 까닭·느낌·방법을 캐릭터가 먼저 말해 버리면 아이는 할 말이 없어지기 때문에, "걱정을 들려주는 것"과 "답을 건네는 것"을 프롬프트 규칙으로 엄격히 구분한다.
- 아이의 발화에서 **8가지 사고 요소**를 끌어내는 것이 목표다: 감정(EMOTION), 공감(EMPATHY), 이유(REASON), 관점(PERSPECTIVE), 해결책(SOLUTION), 결과 예측(RESULT), 요청(REQUEST), 결정(DECISION). 이야기 속 갈등을 함께 풀며 아이가 자기 말로 이 조각들을 말하게 된다.
- "네/아니오"로 끝나는 질문을 금지한다. 캐릭터가 답을 한 글자도 말하지 않았더라도, 아이가 고개만 끄덕이면 되는 자리를 만들면 심판(judge)이 위반으로 잡는다. **아이가 자기 머리에서 꺼내야 할 것이 항상 남아 있도록** 설계했다.

### 평가받는 느낌 없이 말하게 하는 심리적 안전장치
- 캐릭터는 **칭찬도 채점도 하지 않는다.** "정답", "잘했어", "틀렸어" 같은 말이 금지되어 있어, 아이가 시험 보는 기분 없이 이야기 속 인물을 진짜로 돕는 경험을 한다.
- 캐릭터는 **선생님처럼 말하지 않는다.** "이유", "해결 방법", "요소" 같은 학습 용어를 입에 올리지 않고, 옛이야기 속 인물의 말투 그대로 자기 고민을 나눈다.
- 아이가 말을 더듬거나 "몰라요"라고 해도 **말하는 방식을 절대 지적하지 않는다.** ("똑바로 말해", "더듬지 마" 금지) — 6~9세 아이의 더듬음은 정상이며, 다그치면 다음 답이 더 짧아진다는 원칙이 프롬프트에 명시되어 있다.

### 아이 수준에 맞춘 발판(스캐폴딩)
- 아이가 막히면 캐릭터가 질문을 **한 단계만 좁혀 준다**: ① 아이가 쓴 낱말의 뜻을 묻거나, ② 함께 겪은 일로 되돌아가거나, ③ 같은 걱정을 더 작고 구체적인 순간으로 줄인다. 단, 답이 드러날 만큼 좁히는 것은 "너무 갔다(TOO FAR)"로 금지.
- **같은 질문을 같은 말로 반복하지 않는다.** 아이는 반복 질문을 "내 답이 틀렸구나"로 읽기 때문에, 두 번째부터는 반드시 새로운 말로 좁혀서 묻도록 규칙화했다.
- 한 턴에 **걱정 하나만** 얹는다. 두 가지를 한꺼번에 물으면 아이가 막힌다는 것을 전제로 한 규칙이다.

### 서툰 말도 생각으로 인정
- 분석 LLM에 "아이는 어리다. 서툰 문장이라도 생각이 담겨 있으면 인정하라. 철자와 어순은 무시하라. 길이로 깎지 마라"는 보정 규칙이 명시되어 있다. "불쌍해요" 한 마디도 아이 자신의 감정(EMOTION)으로 센다.
- 한국어 특성을 반영해, "왜냐하면" 같은 표지어가 없어도 어미(-니까, -어서, -면)에 실린 인과·조건을 의미로 읽어 이유(REASON)로 인정한다. 어른 기준의 문장 완성도가 아니라 **의미 기준으로 아이의 사고를 포착**한다.

### 자기 효능감을 키우는 되돌려주기
- 미션 모드에서 캐릭터는 아이가 말한 아이디어의 핵심을 **캐릭터 자신의 말로 되짚어 준다** — 아이는 자기 생각이 "중요한 것으로 받아들여지는" 경험을 한다. 이때도 아이 아이디어에 살을 보태지 않는다(보태면 아이 몫이 사라진다).
- 미션에는 틀린 선택이 없다. 어떤 선택이든 이야기가 이어지도록 설계되어, 아이가 결정을 두려워하지 않게 한다.
- 캐릭터는 아이가 한 번 말했다고 바로 수긍하지 않고 **자기 입장을 유지한다** — 아이에게 "설득할 상대"가 계속 남아 있어, 근거를 들어 설득하는 연습이 이어진다.

## 2. 기술적 차별점

### ① 역할이 분리된 3층 파이프라인 (LLM에 결정을 맡기지 않는다)
| 층 | 담당 | 구현 |
| --- | --- | --- |
| 분석 LLM | 아이 발화에서 의도·요지·사고 요소·유효성 **넷만 기록** | `prompts/analysis` + zod strictObject로 경계 강제 |
| 규칙 엔진 | 장면 진행·종료·유도 여부를 **결정** — LLM을 부르지 않는 순수 함수 | `src/llm/domain/decide.ts`, 같은 입력이면 항상 같은 답 |
| 캐릭터 LLM | 정해진 방향대로 **한 줄 연기만** | `prompts/character` |

- 진행 결정을 LLM에 맡기지 않으므로 대화 흐름이 **재현 가능하고 되짚을 수 있다.** 분석 LLM이 결정 필드를 섞어 내면 조용히 무시하지 않고 거부한다.
- 캐릭터의 장면 종료·설정 창작·이름 지어내기가 전부 금지되어, 이야기 시드(seed) 밖으로 대화가 새지 않는다.

### ② 환각을 걸러내는 증거 기반 검출
- 분석 LLM이 사고 요소를 기록할 때 **evidence는 아이 발화 원문의 부분 문자열이어야 한다**(글자 그대로 복사). 후처리에서 원문 대조로 검증해, 원문에 없는 인용이면 그 요소를 버린다 — LLM이 "아이가 이렇게 말했다"고 지어내는 것을 구조적으로 차단.
- 심판(judge) LLM들도 같은 원칙: 판정 근거는 캐릭터 대사에서 그대로 옮긴 조각이어야 하며, 지어낸 인용이 걸리면 그 판정 자체를 버린다.

### ③ LLM-as-Judge 3종 + 골든셋 자동 평가
프롬프트 품질을 감으로 고치지 않고, 심판 LLM 3종이 캐릭터 대사를 채점한 숫자를 보고 고친다:
- **judge_gave_away_element** — 캐릭터가 아이 몫의 답을 대신 말했는지 + "네" 한 마디로 끝나는 자리를 만들었는지(2중 체크)
- **judge_guided_toward_target** — 대사가 아이를 이번 턴의 과녁(목표 요소) 쪽으로 이끌었는지
- **judge_invented_setting** — 시드에 없는 사람·장소·물건·사건을 지어냈는지

세 심판 모두 확신이 없으면 **"판정불가"를 쓰도록 강제** — 찍은 판정이 섞이면 프롬프트 개선 판단의 숫자가 거짓말을 하기 때문. 심판마다 판정 축을 하나로 좁혀 서로의 영역을 침범하지 않게 했다.

### ④ 아이 시뮬레이터로 자동 테스트
- `prompts/child` — 학년(초1/초3)별로 실제 아이처럼 말하는 시뮬레이터 프롬프트. 초1은 한 문장에 "어…, 그게, 막, 근데"가 섞이고, 같은 질문을 다시 받으면 "내가 틀렸나" 하고 더 짧게 답하는 것까지 재현한다.
- 실제 아이 없이도 캐릭터 프롬프트 변경의 효과를 골든셋 회차로 반복 검증할 수 있다. 관리자 작업대(prompt-lab, goldenset, review, runs)에서 회차 실행·채점·리뷰가 돌아간다.

### ⑤ 공급자 이중화와 기록
- LLM 호출 체인: **Gemini 키1 → 키2 → 키3 → (Anthropic)**. 무료 티어 시간당 한도로 측정이 중간에 끊기는 문제를 다중 키로 해결. 어느 키가 막혔는지 상태를 기억하지 않고 항상 키1부터 시작 — 동작이 항상 같아 되짚기 쉽고, 한도가 풀리면 저절로 원래 키로 복귀.
- fallback은 **API 에러/네트워크 실패/타임아웃일 때만** 발동. 응답 품질이 마음에 안 든다는 이유로는 절대 넘어가지 않는다(넘어가면 어느 모델의 문제인지 못 잰다).
- 성공이든 실패든 **모든 시도를 한 행씩 기록**(llm_calls) — "왜 이 턴이 느렸나"를 되짚을 수 있다.

### ⑥ 프롬프트 운영 체계
- 프롬프트는 코드가 아니라 `prompts/<이름>/` 폴더의 파일. **LLM에 나가는 것(보낼것.md)과 사람이 읽는 해설(해설.md)을 파일로 분리**해, 사람용 주석이 LLM에 새어 나가는 사고를 구조적으로 차단(경로 봉인 테스트로 검증).
- 파일을 캐시하지 않아 **md를 고치면 다음 호출부터 바로 반영** — 배포 없이 프롬프트를 반복 개선할 수 있다.

## 3. STT 인식 정확성을 위해 한 것 (Google Cloud Speech-to-Text)

- **원본 그대로 전송**: 브라우저 MediaRecorder가 만든 webm/opus 녹음을 재인코딩 없이 그대로 보낸다(변환 과정의 음질 손실 없음). opus 헤더에 샘플레이트가 있어 잘못된 값을 명시하는 실수도 원천 차단.
- **채널 수 실측 전달**: 마이크 트랙의 실제 channelCount를 읽어 STT config에 넘긴다 — 채널 수 불일치로 인한 인식 실패 방지.
- **아이 발화 특성 반영**: 언어를 ko-KR로 고정하고, 아이 발화는 문장이 짧으므로 `maxAlternatives: 1`로 최상위 후보만 받는다.
- **무음 처리**: 무음이면 빈 문자열("")을 돌려줘 호출자가 재시도를 판단하게 한다 — 무음을 오인식 텍스트로 흘리지 않는다.
- **인식 이후의 보정은 분석 LLM이 담당**: 철자·어순 오류를 무시하고 의미로 판정하라는 규칙([E-YOUNG])이 있어, STT가 아이 발음을 다소 틀리게 받아 적어도 사고 요소 검출이 살아남는다.
- **보안**: API 키는 서버 env에만 두고 클라이언트에 노출하지 않는다(서버 라우트 핸들러에서만 호출).

## 4. TTS 정확성·품질을 위해 한 것 (Gemini 2.5 Flash TTS + 폴백)

- **3단 폴백 체인**: ① Gemini API TTS(스타일 연기 가능) → ② Cloud TTS의 Gemini-TTS → ③ Chirp3-HD(항상 동작하는 안전망). 어떤 경우에도 소리가 끊기지 않으면서, 응답 헤더(X-TTS-Model)로 어느 경로였는지 확인 가능.
- **말투 연기(stylePrompt)**: TTS 전용 모델이 앞머리의 자연어 지시를 말투로 해석하는 특성을 이용해, 캐릭터 감정·말투를 음성 연기로 입힌다.
- **캐릭터별 보이스 페르소나 고정**: 내레이션=Despina, 며느리=Leda, 시아버지=Schedar, 이장님=Sadachbia. Gemini-TTS와 폴백(Chirp3-HD)이 같은 페르소나를 공유해, 폴백이 발동해도 목소리 정체성이 유지된다.
- **합성 캐시(LRU 200개)**: 같은 (보이스·말투·텍스트) 조합은 재합성하지 않는다 — 씬 재진입·호명 반복이 호출 한도(429)를 갉아먹지 않게. Gemini 성공 결과만 캐시하고 폴백 결과는 캐시하지 않아, 키가 살아나면 제 목소리로 돌아온다.
- **한도 초과(429) 대응**: 구글 응답의 retryDelay를 파싱해 그만큼 기다렸다 최대 2회 재시도. 모델 고정 모드(geminiOnly)에서는 실패 원인을 숨기지 않고 그대로 드러낸다.
- **오디오 포맷 처리**: Gemini API가 주는 원시 PCM(16bit mono)에 WAV 헤더를 직접 씌워 브라우저에서 바로 재생 가능하게 변환.

## 5. 프롬프트 구성 요약

| 프롬프트 | 역할 | 핵심 규칙 |
| --- | --- | --- |
| `analysis` | 아이 발화 1건을 분석해 의도·요지·사고 요소·유효성을 JSON으로 기록 | evidence는 원문 그대로 복사, 8요소 각각의 한국어 판정 기준(어미 기반), 목표를 채점 잣대로 쓰지 않음, 서툰 문장 인정 |
| `character` | 옛이야기 캐릭터의 다음 한 줄 생성 | 장면 종료 금지·대답 대신하기 금지·설정 창작 금지·채점 금지·선생님 말투 금지·한 번에 걱정 하나, 막힌 아이 좁혀주기([C-NARROW]/[C-STUCK]) |
| `child` | 학년별 아이 발화 시뮬레이터(테스트용) | 6~9세 말투, 어른 어휘 금지, 모르면 실제로 막히기, 같은 질문엔 더 짧게 답하기 |
| `judge_gave_away_element` | 심판: 캐릭터가 아이 몫을 대신 말했나 + "네"로 끝나는 자리를 만들었나 | 2중 체크, 근거는 원문 인용, 애매하면 판정불가 |
| `judge_guided_toward_target` | 심판: 대사가 아이를 이번 턴 과녁으로 이끌었나 | "아이의 눈이 어디로 가는가"로 판정, 반박 유도도 유도로 인정 |
| `judge_invented_setting` | 심판: 시드에 없는 설정을 지어냈나 | 심판 자신의 옛이야기 기억을 기준으로 삼지 말 것, 감정 표현은 창작이 아님 |
| `mission_reply` | 미션 중 아이 답을 캐릭터가 받아 되짚는 한 줄 | 아이 아이디어에 보태지 않기, 정답/오답 판정 금지, 고정 질문 대신 말하기 금지 |
| `mission_summary` | 미션 종료 후 캐릭터의 마무리 한 줄 | 아이가 정한 것만 되짚기, 빈칸을 캐릭터가 채우지 않기, 남은 걱정이 있으면 가볍게 질문 하나 |
| `report_analysis` | 보호자 리포트 말하기 분석 탭의 문장 전부(그래프 밑 한 줄·역량별 3카드·대표 발화·어휘 팁) | 숫자 계산은 규칙이 하고 여기는 사람 말로 옮기기만, 읽는 사람은 부모(부모 말투), 인용은 규칙이 준 후보에서만 고르기, 장면 이름표는 그대로 찍고 쪼개거나 번호 다시 매기지 않기 |
| `report_guide` | 보호자 리포트 가정 연계 가이드 탭(이야기 질문 3개·일상 질문 3개) | 아이가 실제로 한 말을 이어받아 아이마다 다른 질문, 모자랐던 요소를 겨냥, 한 응답에 말투 둘(설명은 부모에게 해요체·질문은 아이에게 반말) |
