## 0. 배경 — 지금 무엇이 비어 있나

## 2. 용어

- **활동**: 아이가 이야기 하나를 한 번 진행한 것. `story_sessions` 한 행.
- **리포트**: 활동 하나에 대해 만들어진 보호자용 산출물 한 장. `parent_reports` 한 행.
- **지표(metrics)**: 규칙이 세어 낸 숫자·목록. 같은 활동이면 몇 번을 돌려도 같은 값이다.
- **서술(narrative)**: LLM이 쓴 문장. 돌릴 때마다 달라질 수 있다.
- **축**: 시안 오각형의 다섯 칸. 사고 요소를 묶은 것 넷 + 대화 지표 하나(R4).
- **요소**: 발화분석이 찾는 사고 요소 8종 (`src/llm/elements.ts`).

### 4.2 축 점수 (R17)

**축 점수 = 그 축에 묶인 요소가 감지된 발화 수의 합.** 정규화하지 않는다 — 시안 카드의
"이유를 붙인 문장이 이번 활동에서 5번 나왔어요"와 **같은 숫자**여야 하기 때문이다.
그래프의 오각형 크기는 프론트가 `max(axes[*].score)` 로 그 활동 안에서만 맞춘다.

| 축 | 묶는 요소 |
|---|---|
| 관점과 공감 | `PERSPECTIVE` + `EMPATHY` |
| 감정 표현 | `EMOTION` |
| 생각과 이유 | `DECISION` + `REASON` |
| 결과와 해결 | `SOLUTION` + `RESULT` |
| 상호작용 | 요소 아님 (아래) |

⚠️ **「이야기가 요구한 요소 대비 충족률」로 매기지 않는다.** 「방귀 뀌는 며느리」의 대화
4장면이 요구하는 요소를 다 모으면 `PERSPECTIVE·EMPATHY·REASON·SOLUTION·REQUEST·RESULT`
여섯뿐이고 **`EMOTION` 과 `DECISION` 은 한 번도 요구되지 않는다**
(`src/llm/db/seed.ts:292 · :343 · :381 · :415`). 충족률로 매기면 「감정 표현」 축이 항상 0이 된다.

**상호작용 점수 = `child_questions` + `reprompt_recovered` + `soft_cue_answered`**
(R4 · 미정 M1 은 2026-08-15 실측으로 닫혔다 — 아래).

- `child_questions` — `utterance_analyses.child_intent = 'QUESTION'` 인 아이 발화 수
- `reprompt_recovered` — 유도(GUIDED) 턴 **다음** 아이 발화가 `VALID` 인 횟수.
  턴별 모드는 `turn_conditions` 에 남는다 (`src/llm/service/turn.ts:404` 가 매 턴 박제한다)
- `soft_cue_answered` — **soft-cue 가 얹힌 턴 다음** 아이 발화가 그 `guidance_target`
  을 실제로 말한 횟수. soft-cue 는 **아이가 잘 답한 턴에만** 선다(`decide.ts:255` —
  `NORMAL` 이고 새 요소를 말했고 못 채운 요소가 남았을 때). `turn_conditions` 의
  `soft_cue` · `guidance_target` 두 칸을 본다
- `child_turns` 는 참고값으로만 담고 점수에 넣지 않는다 — 말수가 많을수록 커져
  「주고받았나」가 아니라 「많이 말했나」를 재게 된다

⚠️ `soft_cue_answered` 는 **`soft_cue === true` 인 턴만** 센다. `guidance_target` 은
`GUIDED` 턴에도 남으므로 그것까지 세면 `reprompt_recovered` 와 **같은 사건을 두 번
센다** (실측: 나윤은 회복 5점인데 GUIDED 적중도 정확히 5건이었다).

#### 🔴 왜 셋째 항이 생겼나 (2026-08-15 실측 · 미정 M1 종결)

두 항짜리 공식은 **실측 없이 정한 임의값**이었고, 목데이터 12건으로 처음 재 보니
**뒤집혀 있었다.** 「되묻기 회복」은 **먼저 답을 못 해야** 얻는 점수라, 처음부터 잘
답한 아이는 영영 얻을 수 없었다.

| | 옛 공식 | 새 공식 |
|---|---|---|
| 12건 합계 | 22점 | **86점** |
| 활동당 평균 | 1.8점 (다른 네 축은 최댓값 평균 8.5) | **7.2점** — 단위가 맞는다 |
| 민서(가장 풍부하게 말한 아이) | **0점 · 0%** | **8점 · 89%** |
| 점수의 구성 | 22점 중 20점이 「회복」 | 셋이 고루 |

셋째 항은 **가중치를 곱하지 않는다** — 다른 네 축이 전부 「그런 말을 한 발화 수」라는
정수라서 결이 깨진다. 새 항도 **세는 것**이다.

⚠️ **남은 자리 하나 — 「거의 말 없이 중단한 활동」.** 시우(발화 3건)는 모든 축이 0인데
`reprompt_recovered` 한 점만 있어, 활동별 정규화 탓에 오각형에 **바늘 하나**가 선다.
새 항으로는 안 풀린다(soft-cue 기회가 아예 안 생긴다). 화면에서 중단 활동에 오각형을
안 그리거나, `reprompt_recovered` 를 「회복했고 그 발화에 요소가 하나라도 잡혔을 때」로
좁히는 길이 있다. **아직 안 정했다.**

### 4.3 낱말 (R6·R15·R21)

낱말은 **LLM이 뽑고 규칙이 판정한다.** 순서가 중요하다.

1. `report_analysis` 가 아이 발화에서 낱말 목록을 뽑는다 — 기본형으로(「부끄러웠어요」→「부끄럽다」)
2. 규칙이 그 목록을 `child_words`(아이별 누적)와 대조해 **새 낱말**을 가린다
3. 규칙이 그 목록을 장면 낱말 목록(`story_scenes.vocabulary`)과 대조해 **뜻**을 붙인다
4. **질문한 낱말** — 아이의 `QUESTION` 발화 원문에 장면 낱말 목록의 낱말이 있으면 센다.
   LLM을 거치지 않는다 (R15)
5. 새 낱말을 `child_words` 에 넣는다 — **리포트 저장이 성공한 뒤에** 넣는다.
   먼저 넣으면 재생성(R19) 때 그 낱말들이 이미 있어 새 낱말이 0이 된다

⚠️ **첫 활동이면 `child_words` 가 비어 있어 쓴 낱말이 전부 새 낱말이 된다.**
그래서 첫 활동에서는 `new_words` 를 숫자로 보여 주지 않고 「처음 만난 낱말」로 이름을 바꿔
표시한다. 판단 근거는 `metrics.words.new[].is_first_activity` 가 아니라
**그 아이의 이전 완료 활동 수**이며, 집계기가 `metrics.activity.prior_activities` 로 담는다.

## 5. 서술 — LLM이 쓰는 것

프롬프트는 `prompts/<이름>/보낼것.md` · `해설.md` 두 파일 규칙을 그대로 따른다
(`prompts/README.md`). 나가는 쪽은 영어, 판정 예시 발화는 한국어다.

### 5.1 두 편 (R9)

| 폴더 | 무엇 | 태그 머리 |
|---|---|---|
| `prompts/report_analysis/` | 말하기 분석 탭의 문장 전부 + 낱말 추출 | `[A-…]` |
| `prompts/report_guide/` | 가정 연계 가이드 탭의 질문 6개 | `[G-…]` |

### 5.2 `report_analysis` 계약

**받는 재료** (`materialJson` 한 덩이 — 자리표시자를 쓰지 않는다):
`metrics` 전부 + `quotes[]` + 아이 이름·나이 + 이야기·장면 이름.

**내는 것**

```jsonc
{
  "overall": "감정 표현과 상호작용이 특히 잘 드러났어요",
  "cards": [
    { "axis": "어휘",
      "summary": "마음을 나타내는 낱말을 상황에 맞게 골라 썼어요",
      "quote_message_id": "…",
      "did_well":   "'부끄럽다·당당하다' 같은 마음 낱말 7개를 새로 썼어요",
      "to_improve": "'좋다/싫다' 대신 더 구체적인 낱말을 함께 찾아보면 좋아요" }
    // "표현", "논리" 각 한 장 — 축은 셋 고정
  ],
  "highlight": { "quote_message_id": "…",
                 "why": "인물의 마음과 그 이유를 한 문장으로 이어 말해, 지우의 강점이 가장 잘 드러난 말이에요" },
  "word_tip": "오늘 저녁에는 '신기하다' 대신 쓸 수 있는 말을 함께 찾아보면 어휘가 더 넓어질 것 같아요",
  "words": { "extracted": ["부끄럽다", "당당하다", "참다", "신기하다"],
             "repeated":  ["왜냐하면", "그래서", "진짜"] }
}
```

🔴 **`quote_message_id` 는 재료로 준 `quotes[]` 안의 id 여야 한다.** 서버가 대조해
목록 밖이면 그 카드의 인용을 버리고 카드는 인용 없이 남긴다. 근거를 원문과 대조해
어긋나면 버리는 방식은 심판 프롬프트가 이미 쓰는 것이다(`src/llm/judge.ts:429`).

🔴 **그 대조를 우회하는 길이 하나 있었다 — 2026-08-15 에 막았다.** 위 `did_well`·
`why`·`overall`·`word_tip` 은 **자유 문장**이라 서버가 한 글자도 대조하지 않는다.
모델이 그 안에 「"며느리가 불쌍해요"라고 말했어요」를 지어 넣으면 아무 검사도 안 거치고
보호자에게 **아이가 한 말처럼** 나간다. 그래서 두 프롬프트에 「자유 문장 안에서 아이가
말한 **문장**을 따옴표로 감싸지 마라」를 넣었다(`A-NOQUOTE` · `G-NOQUOTE`).

⭕ **낱말 하나를 작은따옴표로 감싸는 것은 그대로다.** 위 예시의 `'부끄럽다·당당하다'`
와 `word_tip` 의 `'신기하다'` 가 그것이고, 화면이 **처음 나오는 작은따옴표 묶음**을
찾아 파랗게 칠한다(`src/lib/report.ts` 의 `splitAccent()`). 금지 대상은 **아이가 말한
문장**이지 낱말이 아니다.

**표현 카드의 근거(R22)** — 음성이 없으므로 프롬프트가 볼 것은 셋뿐이다:
인물 말을 그대로 흉내 낸 **직접 인용**, **의성어·의태어**, **꾸밈말**. 목소리·톤·크기를
말하는 문장은 금지한다.

### 5.3 R5의 유일한 예외 — 낱말 추출

R5는 "근거는 규칙이 뽑는다"인데 낱말만 LLM이 뽑는다(R21). 한국어를 낱말로 쪼개려면
형태소 분석기가 필요한데 이 레포에 없고, 넣지 않기로 했기 때문이다.

**흔들림을 줄이는 장치 둘** — ① LLM은 낱말을 **뽑기만** 하고 「새 낱말인가」는 규칙이
판정한다(4.3). ② 뽑힌 낱말이 실제 발화 안에 글자로 있는지 서버가 대조하고, 없으면 버린다.

### 5.4 `report_guide` 계약

**받는 재료**: 장면별 아이 발화(인용 후보) + 이번 활동에서 **모자랐던 요소** + 아이 이름·나이.

```jsonc
{
  "reason": "이유·결과를 묻는 질문으로 골랐어요",
  "story_questions": [
    { "element": "REASON", "scene_code": "sc_banggui_03", "quote_message_id": "…",
      "question": "왜 부끄러웠을까? 이유까지 말해줄래?",
      "fallback": "\"몰라\"라고 한다면 — \"지우라면 그때 어땠을 것 같아?\"" }
  ],
  "daily_questions": [
    { "label": "내 경험과 이유",
      "question": "지우도 부끄러웠던 적 있어? 왜 그런 마음이 들었어?",
      "goal": "자기 경험의 원인을 설명해보기" }
  ]
}
```

각 배열은 3개 고정. `element` 는 8요소 코드여야 하고, 배지 이름은 프론트가
`elementName()` 로 바꾼다 (`src/llm/elements.ts`).

### 5.5 지켜야 할 것 (두 프롬프트 공통)

- **읽는 사람은 부모다.** 아이에게 하는 말투가 아니다.
- **평가·등수·진단 금지.** "또래보다", "부족합니다", "지연" 같은 말을 쓰지 않는다.
- **보완할 점은 반드시 다음 행동으로.** "~하면 좋아요" 꼴로 끝낸다.
- **이름은 받되 로그로 남기지 않는다** (R12). 로깅 층(`src/llm/log.ts`)이 재료를 통째로
  적는 자리가 있으면 리포트 경로에서는 가린다.
- 이야기 줄거리를 바꾸거나 없는 장면을 지어내지 않는다.

### 5.6 검사에 미치는 영향

`tests/prompts.test.ts` 가 **폴더 여덟과 태그 47쌍을 고정 단언**으로 못박고 있다.
폴더가 열이 되고 태그가 늘므로 그 숫자를 같이 고쳐야 한다 — 안 고치면 먼저 빨개진다.

⛔ **프롬프트 작업대(`/prompt-lab`)의 실험 대상은 늘리지 않는다.** 지금 `analysis` ·
`character` 둘로 세 곳(리포·DB CHECK·화면)에 못박혀 있고, 리포트 프롬프트를 얹으려면
셋을 다 고쳐야 한다. 이번 범위 밖이다 (13절).

## 6. 데이터 모델

### 6.1 새 표 — `parent_reports` (R10)

우리 선언(`src/llm/db/schema.ts`)에 세운다. 저쪽(팀 레포) 표를 건드리지 않는다.

```sql
CREATE TABLE parent_reports (
    id            uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id    uuid        NOT NULL UNIQUE REFERENCES story_sessions (id) ON DELETE CASCADE,
    -- children.id 값. story_sessions.child_id 와 같은 이유로 FK 를 걸지 않는다
    child_id      uuid        NOT NULL,
    status        varchar     NOT NULL CHECK (status IN ('metrics_only', 'complete')),
    metrics       jsonb       NOT NULL,
    narrative     jsonb,                     -- LLM 실패 시 NULL (R18)
    model         varchar,                   -- 어느 모델이 썼나
    prompt_digest jsonb,                     -- {"report_analysis": "sha256…", "report_guide": "…"}
    generated_at  timestamptz NOT NULL DEFAULT now(),
    read_at       timestamptz,               -- 보호자가 처음 연 시각 (빨간 점)
    regenerated   smallint    NOT NULL DEFAULT 0
);
CREATE INDEX idx_parent_reports_child ON parent_reports (child_id, generated_at DESC);
```

- `session_id` UNIQUE — 활동 하나에 리포트 하나(R1). 재생성은 **덮어쓴다.**
- `prompt_digest` 는 골든셋이 쓰는 `promptDigest()` 와 같은 함수로 찍는다
  (`src/llm/service/goldenset.ts`). 프롬프트를 고친 뒤 어느 리포트가 옛 판인지 이걸로 가른다.
- ⛔ **`reports` 표는 손대지 않는다.** 저쪽 표이고, 지금 비어 있으며, 칸이 맞지 않는다.

### 6.2 새 표 — `child_words` (R6)

```sql
CREATE TABLE child_words (
    id           uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
    child_id     uuid        NOT NULL,
    word         varchar     NOT NULL,
    meaning      text,                       -- 장면 낱말 목록에 있으면 붙는다
    first_session_id uuid    REFERENCES story_sessions (id) ON DELETE SET NULL,
    first_scene_code varchar,
    created_at   timestamptz NOT NULL DEFAULT now(),
    UNIQUE (child_id, word)
);
```

⚠️ **저쪽에 `wordbook` 이라는 빈 표가 이미 있다.** 쓰임이 겹치지만 그 표를 쓰지 않는다 —
저쪽 표를 우리 선언에 넣으면 `drizzle-kit push` 가 볼 수 있는 표 목록에 들어가고
(`tablesFilter`, `src/llm/db/push-guard.ts`), 실수 한 번에 남의 표가 날아갈 수 있다.
둘을 합칠지는 팀과 따로 정한다.

### 6.3 늘리는 칸 — `story_scenes.vocabulary` (R20)

ALTER TABLE story_scenes ADD COLUMN vocabulary jsonb NOT NULL DEFAULT '[]';
-- [{ "word": "며느리", "meaning": "아들의 아내" }, { "word": "배나무", "meaning": "배가 열리는 나무" }]

## 7. API (R11)

라우트 파일은 한 줄 재-내보내기, 로직은 `src/report/controller/` 에 둔다 (`src/session/README.md` 규칙).

| 메서드·경로 | 무엇 | 응답 |
|---|---|---|
| `GET /api/children/{child_id}/reports` | 리포트가 있는 활동 목록 (드롭다운) | `[{session_id, story_title, played_at, status, unread}]` |
| `GET /api/reports/{session_id}` | 리포트 한 장 | `{status, metrics, narrative, generated_at, read_at, regenerated}` |
| `POST /api/reports/{session_id}/read` | 읽음 표시 | `204` |
| `POST /api/reports/{session_id}/regenerate` | 다시 만들기 (R19) | `{status, metrics, narrative}` |

**문지기** — 로그인한 보호자의 `parents.id` 로 `children` 을 타고 내려가 그 세션이 자기
아이 것인지 확인한다. 아니면 `404`(존재 여부도 알리지 않는다).

**재생성 제한** — `regenerated >= 3` 이면 `429`. 보호자 손에 비용이 달려 있어서다(R19).
숫자는 설정값으로 두고 코드에 박지 않는다.

**만드는 자리** — 세션이 `completed` 로 바뀌는 지점에서 `generateReport(session_id)` 를
**기다리지 않고** 부른다. 실패해도 아이 화면이 멈추지 않아야 한다(R2·R18).

> 🔴 **이 줄은 2026-08-15 이후 「후활동이 없는 이야기」에만 해당한다** (이슈 #43 ·
> `docs/말하기후활동_명세.md` **7.1절**이 정본이다). 말하기 후 활동이 붙은 이야기
> (`stories.post_activity_config` 가 찬 이야기)는 이야기가 끝나도 **여기서 안 만든다** —
> 아이가 활동을 하나 더 하므로 그 결과까지 담아 한 번에 만든다 (F10). 대신 만드는 자리가
> 셋이다: 후활동 종료 API · 활동을 건너뛰고 끝 화면을 떠난 길 · **보호자가 리포트를 열었는데
> 없을 때의 받침**(F12 — `listChildReports()`·`readParentReport()`가 띄운다).

## 8. 생성 흐름

```
활동 종료 (status → completed)
  │
  ├─① 지표 집계          metrics 계산 (순수 함수, LLM 0회)
  │                      ↳ 실패하면 여기서 끝. 리포트 행을 만들지 않는다
  ├─② report_analysis    LLM 1회 → 인용 id 대조 → narrative 절반
  ├─③ report_guide       LLM 1회 → 인용 id 대조 → narrative 나머지
  │                      ↳ **둘 다** 실패하면 narrative=null · status='metrics_only' (R18)
  │                      ↳ 한 편만 실패하면 **성공한 쪽을 살려** status='complete'
  ├─④ 저장               parent_reports upsert (session_id 로)
  └─⑤ 낱말 누적          child_words 에 새 낱말 넣기 ← ④가 성공한 뒤에만 (4.3)
```

②와 ③은 서로를 안 보므로 **동시에 부른다.** 지연은 둘 중 느린 쪽이다.

### 🔴 「한 편만 실패」를 어떻게 저장하나 (2026-08-15 확정)

**이 줄은 원래 「②나 ③이 실패하면 `metrics_only`」였다.** 그런데 `src/report/types.ts:136`
이 **「`metrics_only` 면 `narrative` 는 `null`」**을 못박고 있어, 그대로 하면 한 편만
실패했을 때 **성공한 절반을 통째로 버리게** 된다. R18 의 뜻은 「실패해도 남은 것을
보여 준다」이므로 **살리는 쪽이 맞다.** 그래서 코드(`src/report/engine/narrative.ts`)
가 이미 하는 대로 확정한다.

| 무슨 일이 있었나 | `status` | `narrative` |
|---|---|---|
| 둘 다 성공 | `complete` | 다 참 |
| **한 편만 실패** | `complete` | **실패한 편의 칸만 빈다** |
| 둘 다 실패 | `metrics_only` | `null` |

⚠️ **실패한 편의 글자 칸은 `null` 이 아니라 빈 글자(`''`)로 온다.** 화면이 `??` 로
받으면 안내 문구 대신 빈 줄이 그려진다 — `src/lib/report.ts` 의 `textOr()` 가 그것을
막는 자리다. 이 계약을 바꾸려면 두 곳을 같이 고쳐야 한다.

## 9. 프론트엔드 — 화면은 따로 들어온다

🔴 **리포트 화면은 이 명세가 만들지 않는다.** 페이지가 따로 들어오고, 우리는 거기에
값을 물린다. 그래서 이 절은 **컴포넌트 구성·좌표·색·반응형을 정하지 않는다** —
그건 페이지가 들어온 뒤 그 페이지를 기준으로 맞춘다.

**우리가 정하는 것은 둘뿐이다.**

1. 화면이 받는 값의 모양 — `docs/보호자_리포트_프론트_계약.md` (타입 · 샘플 응답 2개)
2. 화면이 지켜야 할 규칙 다섯 — 같은 문서 2절

그중 값이 아니라 **동작**이라 여기에도 적어 두는 것:

- 리포트 대상 아이는 선택된 아이 쿠키를 그대로 쓴다 (`requireSelectedChild()`).
- 레이더는 `max(axes[*].score)` 로 그 활동 안에서만 정규화한다 (R17).
- `status='metrics_only'` 이거나 근거가 모자란 칸은 **빈 칸이 아니라 안내 문구**로 채운다 (R16·R18).
- 마이페이지의 진입 카드(`src/components/mypage/parent-report-card.tsx`)는 그대로 둔다 (R24).
  미읽음 점만 붙는다.

⚠️ 시안 `22.svg` · `23.svg` 는 **글자가 전부 `<path>` 로 변환**돼 있어(`<text>` 0개)
그대로 깔고 글자만 갈아끼우는 방식은 쓸 수 없다. 들어오는 페이지가 그 문제를 이미
풀고 있을 것이므로, 우리는 값만 물린다.

## 10. 목데이터 — 아이 10명 (R13·R14)
