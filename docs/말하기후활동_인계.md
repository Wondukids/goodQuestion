### 워크트리 띄우는 법 (Orca)

레시피는 `~/.claude/docs/orca-cli.md` 「병렬 에이전트 오케스트레이션」. 요지는
**킥오프 커밋을 브랜치에 먼저 만들어 두고 → Orca create 로 채택** 순서다.

```bash
# ① 브랜치를 만들고 TRACK-KICKOFF.md 를 커밋해 둔다 (자기 완결 지시서)
# ② 그 브랜치를 Orca 가 채택하면서 에이전트까지 한 방에 띄운다
orca worktree create --name issue-44-retelling-judge \
  --base-branch rlaqudwn1/issue-44-retelling-judge \
  --agent claude --issue 44 \
  --prompt "TRACK-KICKOFF.md 를 읽고 시작해 주세요" --json
# ③ 첫 지시가 들어갔는지 눈으로 확인
orca terminal list --json && orca terminal read --terminal <handle>
```

브랜치 이름은 기존 관례를 따른다 — `rlaqudwn1/issue-<번호>-<짧은-영문>`
(예: `rlaqudwn1/issue-38-report-api`). 폴더는 레포 루트 아래 `issue-42-post-activity` 꼴.

## 4. 🔴 모르고 넘어가면 사고 나는 것 여섯

### ① 시드만으로는 카드·단어가 안 들어간다 (#42)

`src/llm/db/seed.ts` 는 **`stories` 만 `onConflictDoNothing`** 이다 (2026-08-13 결정 4 · 4차).
이미 서 있는 이야기 행에는 시드를 다시 돌려도 `post_activity_config` 가 **안 채워진다.**
값은 `sql/007` 의 `UPDATE` 가 정본이고, `seed.ts` 는 새 DB 를 처음 세울 때만 쓴다.

### ② 표를 늘리면 검사 둘을 함께 고친다 (#42)

`tests/schema.test.ts`(표 목록) · `tests/push-guard.test.ts`(`tablesFilter` 목록).
안 고치면 빨간불이 난다. 표 이름 하나 늘 때마다 두 곳이다.

### ③ `낱말이_발화에_있나()` 를 고치지 마라 (#44)

「참다」의 어간이 「참」 한 글자로 줄어 「참새」에도 걸리는 문제가 있다. 그렇다고
`src/report/engine/verify.ts` 를 고치면 **보호자 리포트의 낱말 세기가 함께 바뀐다** —
거기서는 지금 동작이 맞다(성기게 잡아도 되는 자리다). **부르는 쪽(후활동 판정)에서
두 글자 바닥을 걸어라** (명세 6.1 · 결정 F14).

### ④ 리포트 호출 두 자리는 지우지 말고 조건을 건다 (#43)

`src/llm/service/run.ts:318` · `src/llm/service/story.ts:228` 의 `queueReport()` 는
`#38` 머지(`4fc6982`)로 이미 `api_team` 에 들어와 있다. 지우면 **마무리 활동이 없는
이야기의 리포트가 영영 안 만들어진다.** 그 이야기에 `post_activity_config` 가 **없을 때만**
부르도록 조건을 건다 (결정 F13).

### ⑤ 세션 상태 `post_activity` 를 쓰지 마라 (#43)

한때 그렇게 하려다 접었다(F5). 활동을 안 하고 앱을 꺼버린 아이의 세션이 그 상태에 영영
갇히고, 리포트가 안 나온다. **세션은 지금처럼 이야기가 끝나면 `completed`**, 리포트는
활동 종료 신호로 만든다. 상태 값은 체크 제약과 화면 문구에 남아 있지만 **쓰이지 않는 값**이다.

### ⑥ LLM 판정 실패는 오류가 아니다 (#44·#45)

받아쓴 글은 **판정보다 먼저 저장**하고, 판정이 실패하면 `{ analyzed: false }` 로 **200** 을
준다. `analyzed_at` 은 NULL 로 남는다. 아이 화면은 끝까지 진행된다 (결정 F4·F8).
「판정을 못 했다」와 「단어를 하나도 안 썼다」는 그 칸으로 구별한다.

## 7. 참고 — 이 활동이 미션 1·2 와 다른 점

| | 미션 1·2 | 후활동 |
|---|---|---|
| 여는 신호 | 서버 턴 응답 `next.kind === "미션시작"` | 이야기 끝 화면의 버튼 (사람이 누른다) |
| 표 | `story_missions` · `mission_sessions` · `mission_messages` | `post_activity_results` · `post_activity_keywords` |
| LLM | 미션 대사·종료 요약 | 단어 판정 하나 |
| 세션당 | 여러 번 | 한 번 (`session_id` UNIQUE) |

코드도 안 겹친다 — 후활동은 `finale.tsx` + `finale-script.ts` 두 벌뿐이고 미션 파일을
하나도 부르지 않는다. **어느 갈래에서도 미션 코드에 손대지 않는다.**
