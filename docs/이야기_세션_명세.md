# 이야기 세션 — 시작·이어하기·턴·화면 연결 기획·명세

> 2026-08-14 · `api_team` · 설계 문서 (구현 아님 — 이슈 등록용)
>
> **스코프: 이야기 수준 세션.** 아이가 동화 하나를 처음 열 때부터 끝낼 때까지의
> 서버 상태와 아이 앱 계약, 그리고 화면 연결이다. 대화 턴 하나의 이어하기는
> `docs/대화턴_이어하기_명세.md` (이슈 #2, 구현 중)가 다룬다.

## 0. 배경 — 지금 무엇이 비어 있나

- 플레이어(`src/stories/fart-bride/`)의 진행 위치는 **메모리 속 배열 순번**뿐이다.
  새로고침하면 처음부터고, 캐릭터 대답은 고정 문구다(`buildReaction()`).
- 서버 `story_sessions` 에는 `current_scene_id`(이어할 장면) 칸이 이미 있는데
  아무도 안 쓴다. 인트로의 `startStory()` 서버 액션은 세션 행을 만들기만 하고
  장면을 한 번도 안 써 넣는다. 홈의 「이어서 보기」 카드는 실제로는 처음부터다.
- 대화 엔진(`src/llm`)은 이야기 수준 진행을 이미 안다 — `nextStep()`(다음 할 일 판정),
  `advanceScenes()`(다음 대화 장면까지 전진), `startScene()`(여는 말 `messages` 행 저장).
  이 명세는 그 능력을 **아이 앱 계약으로 노출**하는 일이다. 새로 쓰는 규칙은 장면 매핑표
  하나뿐이다.

## 1. 확정 결정

rev.2 설계에서 승계한 것 (①~⑤)과 이번에 확정한 것 (⑥~⑧):

| # | 결정 | 근거 |
|---|---|---|
| ① | 대화 진행은 세션 도메인(`src/session`)이 맡고 `src/llm` 은 LLM만 | rev.2 |
| ② | 아이 앱은 요청 1번 = 턴 1개. 관리자 `/api/v1/*` 3단계는 그대로 | rev.2 |
| ③ | 재개 지점 = 그 장면의 마지막 캐릭터 `messages` 행. 새 표 0개 | rev.2 |
| ④ | 합성 오디오 저장 안 함. TTS는 앱이 직접, 서버 시퀀스의 외부 호출은 STT 하나 | rev.2 |
| ⑤ | 미완 턴은 죽은 단계부터 마저 돌린다 | 이슈 #2 |
| ⑥ | **세션 생성 시 회차(`runs`) 한 행을 함께 만든다** — `started_by='app'`, `scope='story'` | `llm_calls.run_id` 가 NOT NULL. 스키마·기존 코드 무변경의 유일한 길 |
| ⑦ | **복귀 연출은 직전 영상부터** — 재개 대화 장면 바로 앞 영상 한 편을 다시 튼 뒤 대화로 | 아이가 맥락을 되찾는다 |
| ⑧ | **진행 지휘권: 대화 장면만 서버가 안다** — 영상 구간은 프론트가 자기 순번으로 진행하고 서버에 보고하지 않는다 | 영상 재생 위치를 저장하지 않는다는 rev.2 결론과 일치. 변화 최소 |

## 2. 용어

- **세션**: 아이 1명의 동화 1회 플레이 전체 (`story_sessions` 한 행). 장면을 건너며 이어진다.
- **회차(run)**: LLM 호출 기록(`llm_calls`)의 묶음 단위 (`runs` 한 행, 세션과 1:1).
- **장면(scene)**: 서버의 진행 단위 (`story_scenes`). `character_id` 가 있으면 대화 장면.
- **스텝(step)**: 플레이어의 진행 단위 (`data.ts` `SEQUENCE` 의 원소 — 영상 part 또는 대화).
- **턴**: 아이 발화 1건 + 캐릭터 대사 1건.

## 3. 장면 매핑 — 번호가 세 벌이다

같은 이야기를 세 곳이 다른 번호로 부른다. 조인 키는 이야기가 `stories.slug`
(= 플레이어 등록 키 = `'fart-bride'`), 장면이 `story_scenes.code` 다.

| 서버 `story_scenes` | 성격 | 플레이어 스텝 id | 기획 원본 번호 (1~18) |
|---|---|---|---|
| `sc_banggui_01`·`02` | 영상 | `part1` | 1~3 |
| **`sc_banggui_03`** | **대화** | **`scene4`** | 4 |
| `sc_banggui_04` | 영상 | `part2` | 5~6 |
| **`sc_banggui_05`** | **대화** | **`scene7`** | 7 |
| `sc_banggui_06` | 영상 | `part3` | 8~9 |
| **`sc_banggui_07`** | **대화** | **`scene10`** | 10 |
| `sc_banggui_08` | 영상 | `part4` | 11~15 |
| **`sc_banggui_09`** | **대화** | **`scene16`** | 16 |
| (없음) | 엔딩 영상 | `part5` | 17~19 |

- 결정 ⑧에 따라 **런타임에 필요한 매핑은 대화 4쌍뿐이다**. `data.ts` 의
  `InteractiveStep` 에 `sceneCode: string` 필드를 더해 원천을 프론트에 둔다
  (기존 `sceneId` 는 기획 번호로 유지).
- 「직전 영상」은 서버가 계산하지 않는다 — `SEQUENCE` 에서 재개 대화 스텝 바로 앞
  원소가 그 영상이다.
- `part5`(엔딩)는 서버 장면이 없다. 마지막 대화가 끝나 서버가 `회차끝` 을 주면
  앱이 틀고 끝낸다.

## 4. API 계약 (아이 앱)

경로·응답 봉투·오류 코드는 이슈 #2 가 확립한 것을 그대로 쓴다:
`/api/sessions/*`, 성공 `{ ok: true, data }`, 실패 `{ ok: false, error: { code, message, retryable, pending? } }`.
아이 확인(`selected_child` 쿠키 → `child_id`)은 **컨트롤러 입구에서 한 번** 하고,
그 아래로는 불투명 값으로만 다룬다 (두 DB를 한 트랜잭션으로 못 묶는다 — rev.2 7절).

### 4.1 `POST /api/sessions` — 세션 열기 (시작 + 이어하기 + 따라잡기)

- 요청: `{ story: string }` (slug).
- 동작 (반복 안전):
  1. `(child_id, story_id, status='in_progress')` 세션을 찾는다. 없으면
     **세션 + 회차를 한 트랜잭션으로 생성**하고(결정 ⑥) 첫 대화 장면까지 전진한다
     (`advanceScenes()` — 여는 말 `messages` 행이 여기서 생긴다).
  2. 있으면 **따라잡는다**: 현재 장면이 끝난 상태(`scene_end_reason` 있음)면 다음
     대화 장면까지 전진. 회차가 없는 행(과거 `startStory()` 흔적)이면 회차를 만들어
     붙이고 1처럼 전진한다 — 마이그레이션 없이 legacy 행이 산다.
  3. 현재 대기 상태를 반환한다.
- 응답:

```json
{ "ok": true, "data": {
    "session_id": "…", "resumed": true,
    "scene": { "scene_id": "…", "code": "sc_banggui_05" },
    "last_character_line": { "message_id": "…", "text": "…" },
    "pending_turn": null } }
```

- `scene` 은 세션이 아이를 기다리는 한 **항상 대화 장면**이다 (`advanceScenes()` 가
  영상 장면을 통과하므로 — rev.2 확인). `last_character_line` 은 그 장면의 마지막
  캐릭터 행 — 여는 말도 캐릭터 행이라 **항상 존재한다** (`startScene()` 이 저장).
- `pending_turn` 이 있으면 앱은 **resume 부터 부른다** (대화턴 명세 4.3).
- 세션이 `completed` 등이면 `scene: null` + `status` 로 분기 (새로 시작은 새 세션).
- 기존 `startStory()` 서버 액션은 이 API 로 대체한다.

### 4.2 `GET /api/sessions/{session_id}` — 읽기 전용 조회

4.1 응답과 같은 모양 + `status` + `progress: { scene_order, total }`.
**상태를 바꾸지 않는다** (따라잡기 없음) — 홈 「이어서 보기」 카드의 진행률 표시용.
플레이 진입은 4.1 이 맡는다.

### 4.3 `POST /api/sessions/{session_id}/turns` — 턴 하나

- 요청: 녹음 오디오 바이너리 (`application/octet-stream` + `X-Audio-Channels` —
  기존 `/api/fart-bride/stt` 라우트와 같은 방식).
- 서버 안 순서: STT → `analysisStep` → `decisionStep` → `dialogueStep`
  (세션 서비스는 `llm/service` 층만 부른다 — rev.2 경계).
- **빈 발화·무음**: 서버 상태 불변(기존 규칙 — `messages` 행이 안 생긴다),
  200 `{ "empty": true }`. 재시도 연출은 프론트 `STT_DEFAULTS` 그대로.
- 성공 응답 — resume 응답(대화턴 명세 4.2)에서 `resumed_from` 을 뺀 모양 + 장면 전진:

```json
{ "ok": true, "data": {
    "child":    { "message_id": "…", "text": "받아쓴 아이 발화" },
    "dialogue": { "message_id": "…", "text": "캐릭터 대사", "source": "generated" },
    "next":     { "kind": "발화받기 | 장면끝 | 회차끝",
                  "scene_id": "…",
                  "next_scene": { "scene_id": "…", "code": "sc_banggui_07" } } } }
```

- **장면 전진은 이 요청 안에서 끝낸다**: 판정이 CLOSING 으로 장면이 끝나면 같은 요청에서
  다음 대화 장면까지 전진(다음 여는 말 저장)하고 `next_scene` 을 싣는다. 다음 대화가
  없으면 `kind: "회차끝"` (엔진이 세션·회차를 닫는다 — `completeRun()`). 그래서 영상을
  보다 이탈해도 서버 기준 재개 지점은 이미 다음 대화 장면이고, 결정 ⑦의 「직전 영상」이
  자연히 그 사이 영상이 된다.
- 미완 턴이 있으면 409 `TURN_INCOMPLETE` + `pending` (이슈 #2 문지기). 앱은 resume 을
  부른 뒤 이어간다. resume 응답이 `장면끝` 이면 앱은 4.1 을 다시 불러 따라잡는다.
- 오류 코드 표는 이슈 #2 의 봉투(`envelope.ts`)를 공유한다.

### 4.4 `POST /api/sessions/{session_id}/turns/resume`

이슈 #2 그대로. 이 명세는 계약을 바꾸지 않는다.

## 5. 화면 흐름 — 시작부터 끝까지

```
[홈/인트로]
   └─ POST /api/sessions
        ├─ resumed=false → part1 부터 (지금과 같음)
        └─ resumed=true  → pending_turn 있으면 resume 먼저
                           → scene 을 sceneCode 매핑으로 스텝으로 변환
                           → goTo(그 스텝 바로 앞 영상)          … 결정 ⑦
                           → 영상 끝 → 대화 진입, last_character_line 을 TTS 재생
[대화 장면]
   └─ 마이크 → POST …/turns (오디오)
        ├─ next.kind=발화받기 → dialogue 를 TTS 재생 → 다시 마이크
        ├─ next.kind=장면끝   → dialogue(닫는 말) 재생 → 다음 영상 스텝으로
        └─ next.kind=회차끝   → 닫는 말 재생 → part5(엔딩) → 종료 화면
[영상 구간]  프론트 순번 진행 · 서버 보고 없음                    … 결정 ⑧
```

수용하는 트레이드오프: 영상 도중 이탈하면 복귀 시 그 영상을 처음부터 다시 본다
(영상 재생 위치는 저장하지 않는다 — rev.2 결정 유지).

## 6. 프론트 변경 목록 (화면 붙이기 이슈의 스코프)

1. `data.ts`: `InteractiveStep.sceneCode` 추가 (3절 매핑 4쌍).
2. 플레이 진입: `startStory()` 액션 → `POST /api/sessions` 로 교체하고, 응답으로
   시작 스텝을 정한다 (`goTo()`).
3. `interactive-scene.tsx`: 고정 문구(`buildReaction()`)와 프론트 STT 직접 호출을
   걷어내고 녹음 블랍을 턴 API 로 보낸다. 캐릭터 답은 `dialogue.text` 를 TTS 로.
   실패(502) 시 기존 고정 문구로 폴백. 여는 말 연출(질문 이미지·녹음 음성)은 당분간
   기존 그대로 두고, 서버 여는 말 행은 재개 표식으로만 쓴다.
4. 홈 「이어서 보기」 카드: `GET /api/sessions/{id}` 의 `progress` 로 진행률을 채우고
   플레이 화면으로 직접 진입.
5. `docs/llm-guide.md` 의 `POST /api/fart-bride/llm` 제안은 **폐기** — 이 명세의 턴
   API 가 대체한다 (문서에 표기).

## 8. 수용 기준

1. 새 아이·새 이야기로 4.1 → 세션·회차(`started_by='app'`)가 한 트랜잭션으로 생기고,
   `scene = sc_banggui_03`, `last_character_line` = 그 장면 여는 말.
2. 같은 몸으로 4.1 을 다시 → 같은 `session_id`, `resumed: true`, 행 수 불변.
3. 턴을 돌려 장면을 끝내면(`CLOSING`) 응답에 `next_scene` 이 실리고, 그 장면 여는 말
   행이 이미 저장돼 있다.
4. 마지막 대화 장면을 끝내면 `회차끝` · 세션 `completed` · `runs.ended_at` 채워짐.
5. 회차 없는 legacy `in_progress` 세션에 4.1 → 회차가 생기고 정상 진행.
6. 빈 발화 → `{ empty: true }` · `messages` 행 수 불변.
7. 미완 턴 상태에서 4.3 → 409 `TURN_INCOMPLETE`; resume 후 4.3 정상.
8. 화면: 대화를 한 번 끝내고 앱을 껐다 켜면 직전 영상부터 재생되고, 대화 진입 시
   마지막 캐릭터 대사가 들린다.
