## 0. 배경 — 지금 무엇이 비어 있나

- 미니게임 두 개(미션1 배 따기 소품 고르기 · 미션2 친구 고민 돕기)는 화면만 있다
  (`src/stories/fart-bride/minigame/`). 아이 발화는 STT 후 화면에 잠깐 떴다 버려지고,
  세션·LLM·DB 연결이 0건이다. 팝업은 SPACE 순환으로만 열리며 이야기 진행과 무관하다.
- 미션2에서 "며느리가 아이 말에 감탄하는 컷"(시안 04)은 LLM 없이는 채울 수 없어
  의도적으로 빠져 있다 — 이 명세의 「아이대답요약」이 그 자리를 되살린다.
- 대화 엔진에는 발화 하나를 **받아쓰기(STT) → 발화분석(LLM) → 판정(순수 함수) →
  캐릭터 대사(LLM)** 로 처리하고 씬의 필수 사고 요소를 누적하는 파이프라인이 이미 있다.
  이 명세는 그 파이프라인을 미션 안으로 끌어들이는 일이다.

## 1. 확정 결정

2026-08-14 인터뷰 두 차례로 확정:

| # | 결정 | 내용·근거 |
|---|---|---|
| M1 | **트리거는 룰베이스** | `decide()` 와 같은 결의 순수 함수로, 기획서의 노출 조건을 요소 감지 + 턴 수로 근사. 규칙은 미션 정의의 `config.trigger` 에 데이터로 둔다. 근사가 무디면 LLM 판정 추가 여지(13절) |
| M2 | **요약은 기존 3단 파이프라인 재사용** | 「아이대답요약」은 별도 요약 엔진이 아니라 분석→판정→캐릭터 LLM 을 미션 턴에도 그대로 태워, 분석 요지(main_point)와 판정 결과를 재료로 캐릭터 LLM 이 생성 |
| M3 | **요소만 합산** | 미션 발화의 요소는 씬 누적(`accumulated_elements`)에 합산하되 미션 턴은 씬 턴 수에 세지 않는다. 미션 후 부족 요소는 유도 대화(GUIDED)로 이어 묻는다 |
| M4 | **재개는 처음부터** | 미션 도중 이탈하면 그 시도는 `abandoned`, 복귀 시 처음부터. 합산된 요소는 유지되므로 손해 없음. 미션 턴의 이어 돌리기(resume)는 만들지 않는다 |
| M5 | **미션 대화는 별도 표** | `mission_messages` 에 따로 저장. 본 대화(`messages`)에는 종료 요약 캐릭터 행 **1개만** 삽입 — 재개 지점 규칙(마지막 캐릭터 행)과 후속 대화 컨텍스트에 자동 반영 |
| M6 | **닫는 말은 한 번 — 미션이 닫으면 답변 컷 스킵** | 미션1 마무리와 답변 컷(n19-2)의 대사가 글자까지 같다. 미션 경유로 씬이 닫히면 닫는 말은 미션 흐름이 말하고 앱은 답변 컷을 건너뛴다. 대화 턴 경유 닫힘은 기존 동작 그대로(중복 없음 — 미션 자체 closing 은 짧은 문장뿐) |
| M7 | **미션2는 즉발 허용** | 첫 대답에서 PERSPECTIVE 가 감지되면 1턴 만에도 발동. 씬이 최대 4턴이라 빨리 미션으로 넘어가는 쪽을 택함 |
| M8 | **재생은 패널→팝업→패널** | 다리 대사(미션 진입)는 대화 패널이 재생 완료 후 팝업을 열고, 종료 요약·닫는 말은 팝업이 닫힌 뒤 대화 패널이 재생. 팝업이 열린 동안 배경·대화 오디오는 일시정지 |
| M9 | **되묻기 1회는 두 미션 공통** | 분석의 SHORT/UNCLEAR 이면 스텝당 1회 되묻고, 두 번째도 짧으면 그대로 진행. 프론트의 「6자 미만」 클라이언트 규칙은 서버 판정으로 대체. 미션1 되묻기 문구는 config 에 추가 |

## 2. 용어

- **미션**: 대화 씬에 끼어드는 미니게임 1종 (`story_missions` 한 행 — 정의·상수).
- **미션 세션**: 한 플레이에서 미션 1회 시도 (`mission_sessions` 한 행).
- **미션 턴**: 미션 안에서 아이 발화 1건 + 캐릭터 대사 1건. 씬 턴 수에 세지 않는다(M3).
- **선택 이벤트**: 말이 아닌 입력 — 소품·친구 카드 탭, 계속/그만, 무음 건너뜀.
- **다리 대사**: 트리거 턴의 캐릭터 대사. 아이 제안을 되짚고 미션 질문으로 연결한다.
- **요소**: 발화분석이 찾는 사고 요소 8종 (`src/llm/elements.ts`).

## 3. 미션 ↔ 씬 대응

| 미션 | `code` | 유형 | 씬 | 캐릭터 | 씬 필수 요소 (DB 시드) | 권장/최대 턴 |
|---|---|---|---|---|---|---|
| 미션1 배 따기 | `ms_banggui_pear` | `prop_choice` | `sc_banggui_07` (대화3) | 마을 이장 | SOLUTION·REASON·REQUEST·RESULT | 3 / 5 |
| 미션2 친구 돕기 | `ms_banggui_friend` | `card_help` | `sc_banggui_09` (대화4) | 며느리 | EMPATHY·PERSPECTIVE·RESULT·SOLUTION | 2 / 4 |

기획서 표에는 대화4 요소에 EMOTION 이 있으나 DB 시드는 EMPATHY 로 확정돼 있다
(`src/llm/db/schema.ts` 의 「EMOTION 은 EMPATHY 로 확정」 주석). 이 명세는 DB 값을 따른다.

씬 안에서의 자리: 여는 말 → 자유 대화 턴 ×N → **(트리거) 미션 구간** → 요약 행 삽입 →
부족 요소 유도 대화 → 닫는 말. 미션이 없는 씬(대화1·2)은 `story_missions` 행이 없어
이 명세의 어떤 경로도 타지 않는다.

## 4. 미션 턴 파이프라인 — 일반 턴과 무엇이 같고 다른가 (M2)

| 단계 | 일반 턴 | 미션 턴 |
|---|---|---|
| ① 받아쓰기 | STT | 같음 (같은 라우트 방식) |
| ② 발화분석 | `analyze()` + `prompts/analysis` + 씬 `element_criteria` | **완전히 같음** — 프롬프트·기준·후처리(`postProcess`) 재사용 |
| ③ 판정 | `decide()` — 모드·닫힘·유도 | **`decideMissionTurn()` 신설** (순수 함수) — 요소 합산·스텝 진행·되묻기 |
| ④ 대사 | `characterTurn()` + `prompts/character` | **`missionReply()` 신설** + `prompts/mission_reply` — 아이대답요약 |
| 저장처 | `messages` · `utterance_analyses` · `turn_conditions` | `mission_messages` (분석은 행 안 jsonb 사본) |
| 세션 갱신 | 요소 합산 + 턴 수 +1 + 유도 카운터 | **요소 합산만** (`accumulated_elements`) — 턴 수·카운터 불변 (M3) |

지연: 미션 턴도 LLM 직렬 2회라 일반 턴과 같은 급(~20초). 종료 요약(LLM 1회)은
`complete` 요청으로 분리해 앱이 마무리 대사를 재생하는 동안 돌린다(7절 D).

## 5. 트리거 규칙 (M1)

판정 시점: **판단 단계 직후**, 그 씬에 미션이 정의돼 있고 완료된 시도가 없을 때만.

```
발동 = (config.trigger.any_elements 중 하나 ∈ 이번 턴 감지 ∪ 씬 누적)
    OR (씬의 아이 턴 수 ≥ config.trigger.min_turns)
```

| 기획서의 노출 조건 | 룰베이스 근사 |
|---|---|
| 아이가 며느리의 방귀를 활용할 수 있다고 제안 | 미션1: **SOLUTION 감지** 즉시 발동 |
| 해결 방향은 있는데 방법이 구체적이지 않음 | SOLUTION 감지에 포함 — 구체화 자체가 미션의 일 |
| 2회 이상 대화했지만 실행 방법이 안 나옴 | **min_turns = 2** 폴백 |
| 캐릭터 질문만으로 구체화하기 어려움 | 위 둘의 합집합으로 흡수 (부족하면 LLM 판정 추가 — 13절) |
| 미션2: 부끄러워하지 않아도 된다고 말함 → 이유 확인 → 관점 확장 | 미션2: **PERSPECTIVE 감지** 즉시(M7 즉발 허용) 또는 min_turns=2 |

**닫힘 게이트**: 미션 씬에서 미션 실행 전에 `decide()` 가 CLOSING 을 내면 CLOSING 대신
트리거를 발동한다 — 기획의 닫힘 조건 「미션 필수 장면에서는 미션과 핵심 발화가 완료된
경우」의 코드화. 미션 없는 씬은 게이트 자체가 없다.

## 6. 데이터 모델 — 새 표 3개 (`sql/005_missions.sql`)

미션 대화가 `mission_messages` 에만 쌓이므로 미완 턴 판정 `pendingTurn()` 의
「마지막 아이 발화의 바로 다음 한 행」 규칙을 건드리지 않는다. 본 대화로 넘어가는 것은
종료 요약 행 하나뿐이다(M5).

```sql
CREATE TABLE story_missions (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  story_id      uuid NOT NULL REFERENCES stories(id) ON DELETE CASCADE,
  scene_id      uuid NOT NULL REFERENCES story_scenes(id),
  code          varchar NOT NULL,          -- 'ms_banggui_pear' / 'ms_banggui_friend'
  title         varchar NOT NULL,
  mission_type  varchar NOT NULL CHECK (mission_type IN ('prop_choice','card_help')),
  mission_goal  text NOT NULL,             -- LLM 재료용 미션 목적 한 문장
  config        jsonb NOT NULL,            -- 트리거·소품/카드·스텝·고정 대사 (아래)
  UNIQUE (story_id, code),
  UNIQUE (scene_id)                        -- 씬당 미션 1개 (MVP)
);

CREATE TABLE mission_sessions (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  session_id    uuid NOT NULL REFERENCES story_sessions(id) ON DELETE CASCADE,
  mission_id    uuid NOT NULL REFERENCES story_missions(id),
  status        varchar NOT NULL DEFAULT 'in_progress'
                CHECK (status IN ('in_progress','completed','abandoned')),
  current_step  varchar,                   -- 관찰용. 재개엔 쓰지 않는다 (M4)
  selections    jsonb NOT NULL DEFAULT '[]', -- [{step, kind, value, at}]
  summary_text  text,                      -- 종료 요약 (LLM 결과 원문)
  started_at    timestamptz NOT NULL DEFAULT now(),
  completed_at  timestamptz
);
-- 같은 미션의 진행 중 시도는 세션당 1개
CREATE UNIQUE INDEX ux_mission_sessions_active
  ON mission_sessions (session_id, mission_id) WHERE status = 'in_progress';

CREATE TABLE mission_messages (
  id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  mission_session_id  uuid NOT NULL REFERENCES mission_sessions(id) ON DELETE CASCADE,
  turn_order          integer NOT NULL,    -- 미션 안 순번
  speaker_type        varchar NOT NULL CHECK (speaker_type IN ('child','character','system')),
  step                varchar,             -- 'use' | 'request' | 친구 id …
  text                text NOT NULL,
  stt_raw_text        text,
  analysis            jsonb,               -- 아이 행만. utterance_analyses 와 같은 모양의 사본
  line_source         varchar CHECK (line_source IN ('fixed','generated','summary')),
  created_at          timestamptz NOT NULL DEFAULT now(),
  UNIQUE (mission_session_id, turn_order)
);

-- 미션 LLM 호출이 기록에 남도록 purpose 확장 (제약 이름은 마이그레이션 때 실물 확인)
ALTER TABLE gq_admin.llm_calls DROP CONSTRAINT llm_calls_purpose_check;
ALTER TABLE gq_admin.llm_calls ADD CONSTRAINT llm_calls_purpose_check
  CHECK (purpose IN ('analysis','character','mission_reply','mission_summary'));
```

- `scene_end_reason` 은 넓히지 않는다 — 미션 완료로 닫혀도 사유는 요소 충족이라 `GOAL_MET`.
- 드리즐 사본(`src/llm/db/schema.ts`)과 시드(`seed.ts` — `story_missions` 2행)를 함께 얹는다.

컷 플랜(확정 결정 ⑨)이고, 서버는 `story_scenes.character_closing` 으로 돌려준다(7절 D).

## 7. API 계약 — 아이 앱 봉투 그대로

경로·봉투(`{ok,data}`)·오디오 방식(octet-stream + `X-Audio-Channels`)은 세션 명세 계약을
그대로 쓴다. 신설은 B·C·D 세 엔드포인트와 A·E 의 응답 확장이다.

### A. 기존 턴 응답 확장 — 트리거는 여기서 발동한다

`POST /api/sessions/{sid}/turns` 응답의 `next.kind` 에 `"미션시작"` 이 추가된다.
트리거 턴의 `dialogue` 는 **다리 대사**다 — 캐릭터 LLM 이
`direction.kind="bridge_into_mission"` 지시를 받아 아이 제안을 되짚고 미션 질문으로
연결한다(고정 도입 문구가 아이 말과 어긋나는 문제가 없다). 이 순간 서버는
`mission_sessions` 행을 만든다.

```json
"next": { "kind": "미션시작", "scene_id": "…",
  "mission": { "mission_session_id": "…", "code": "ms_banggui_pear",
               "mission_type": "prop_choice", "config": { "…": "items·steps·closing…" } } }
```

다리 대사 단계에서 LLM 이 죽으면 일반 턴과 같은 미완 턴이다 — resume 이 대사만 다시
만들고, resume 응답에도 `next: 미션시작` 이 실린다(미션 세션 행은 판정 커밋에서 이미
생겼으므로 반복 안전).

### B. `POST /api/sessions/{sid}/missions/{msid}/events` — 선택·건너뜀

말이 아닌 입력을 기록한다. 서버는 `selections` 에 적고, 그 스텝의 고정 대사를
`mission_messages` 캐릭터 행(`fixed`)으로 저장한 뒤 돌려준다. TTS 는 결정 ④대로 앱이 직접.

```json
요청  { "type": "prop_select" | "friend_select" | "more" | "skip", "value": "sokuri" }
응답  { "ok": true, "data": {
        "line": { "text": "소쿠리 말인가? …", "source": "fixed" },
        "step": "use", "mic": true, "done": false } }
```

- `more`=no 또는 4명 모두 도움 → `done: true`, `line: null` — 앱은 D 를 부른다.
- `skip`(무음 재시도 소진): system 행으로 기록하고 다음 스텝 — 현행 「다음으로」의 승계.

### C. `POST /api/sessions/{sid}/missions/{msid}/turns` — 미션 턴

요청은 기존 턴과 같은 오디오 바이너리. 서버 안 순서는 4절 파이프라인. 무음은 기존
규칙대로 `{ empty: true }` + 상태 불변.

```json
응답  { "ok": true, "data": {
  "child":    { "text": "받아쓴 아이 발화" },
  "dialogue": { "text": "보자기로 배를 받자는 거구나! 떨어져도 안 다치겠어.", "source": "generated" },
  "elements": { "gained": ["SOLUTION","RESULT"], "missing": ["REQUEST"] },
  "next": { "kind": "미션계속", "step": "request",
            "fixed_line": { "text": "그것 좋은 생각이군. …" } } } }
```

- 마지막 스텝이면 `next.kind: "미션끝"` — 앱은 `dialogue` 와 `config.closing` 을 재생하며
  D 를 병렬로 부른다.
- **되묻기(M9, 두 미션 공통)**: 분석 `utterance_validity` 가 SHORT/UNCLEAR 이고 그 스텝의
  첫 시도면 `dialogue: null` + 같은 `step` + `fixed_line`(미션1은 config.reask, 미션2는
  친구별 reask). 두 번째도 짧으면 그대로 진행. 프론트 「6자 미만」 규칙은 삭제.
- **실패 시**: LLM 결과까지 모아 마지막에 한 번에 커밋한다(수집 후 일괄 insert —
  `llm_calls` 는 실패도 남는 기존 규칙대로 트랜잭션 밖). 502 면 미션 상태가 안 변하고
  앱은 재녹음을 유도한다. 미션에는 이어 돌리기가 없다(M4).

### D. `POST /api/sessions/{sid}/missions/{msid}/complete` — 종료 요약

body 없음, 반복 안전(이미 완료면 저장된 요약을 다시 반환). 서버 동작:

1. 미션 대화 전체 + 선택 기록으로 종료 요약 대사 생성 (`mission_summary`).
2. `summary_text` 저장, status=`completed`.
3. 본 대화 `messages` 에 요약 캐릭터 행 삽입 (`utterance_source: 'mission_summary'`).
4. 씬 닫힘 판정: `missing = required_elements − accumulated_elements` **산식만 계산한다.
   `decide()` 를 다시 부르지 않는다** — decide 는 「이번 발화의 분석」이 입력인 함수인데
   완료 시점엔 새 발화가 없다. 같은 이유로 `turn_conditions` 박제도 없다(턴이 아니므로).
   - **missing 없음** → 씬을 닫는다: `scene_end_reason='GOAL_MET'`, 닫는 말
     (`character_closing`) 행 저장, 턴 API 와 같은 방식으로 다음 대화 씬까지 전진.
     응답에 `closing_line` 을 실어 **앱이 재생하고 답변 컷을 건너뛴다**(M6).
   - **missing 있음** → `next: 발화받기`. 요약 대사가 남은 요소의 걱정 한 줄
     (`remaining_worries`)을 받아 유도 질문으로 끝나게 생성된다.

```json
응답  { "ok": true, "data": {
  "summary":  { "message_id": "…", "text": "네 덕분에 정했어! 보자기로 배를 받고, …" },
  "closing_line": { "text": "아이고, 방귀 뀌는 며느리 덕분에 …" } | null,
  "elements": { "accumulated": ["…"], "missing": [] },
  "next":     { "kind": "발화받기" | "장면끝" | "회차끝", "next_scene": { "…": "…" } } } }
```

complete 를 못 부르고 이탈하면(마지막 스텝까지 끝냈어도) 시도는 `abandoned` 로 남고
복귀 시 처음부터다(M4) — 서버가 대신 완료 처리하지 않는다.

### E. 세션 열기(4.1) 확장 + 가드

- 세션 열기 응답에 `mission` 필드: 현재 씬에 `in_progress` 시도가 남아 있으면
  `abandoned` 처리 후 **새 시도를 만들어** 실어 준다 — 앱은 팝업을 처음부터 연다(M4).
  완료된 미션은 다시 노출하지 않는다.
- **409 `MISSION_IN_PROGRESS`** (신규): 미션 진행 중 일반 턴 거절. 미션 API 는 해당
  시도가 `in_progress` 가 아니면 409 `MISSION_NOT_ACTIVE`.
- 미션 API 도 기존 회차 잠금(동시 호출 409 `TURN_IN_PROGRESS`)을 공유한다.

## 8. 진행 흐름

### 미션1 배 따기 — 한 판

```
아이 "방귀로 떨어뜨리면 돼요!" → POST …/turns
  서버: 분석(SOLUTION 감지) → 트리거 발동 → mission_sessions 생성 → 다리 대사 LLM
  응답: dialogue(다리 대사) + next: 미션시작(config)
앱: 패널에서 다리 대사 재생 완료 → 배경·대화 오디오 일시정지 → 팝업 열기 (M8)
소품 탭 → events(prop_select) → 고정 대사("소쿠리 말인가? …") TTS
아이 대답 → 미션 turns → 분석 → 판정(요소 합산) → 아이대답요약
  응답: dialogue(요약) + fixed_line(부탁 질문) + next: 미션계속
아이 대답 → 미션 turns → 요약 + next: 미션끝
앱: 요약 + config.closing("그래! 그렇게 말하면 되겠구려") 재생 ∥ complete 호출
  서버: 미션 전체 요약 LLM → messages 에 요약 행 → 요소 평가
팝업 닫기 → 패널에서 summary 재생
  → 장면끝이면 closing_line(배 잔치) 재생 → 답변 컷 스킵 → 다음 스텝 (M6)
  → 발화받기면 마이크 → 유도 대화 계속
```

### 미션2 친구 돕기 — 스텝 순환

구조는 미션1과 같고 카드 선택이 반복된다. 며느리의 감탄 대사(시안 04에서 뺐던 컷)가
미션 턴의 아이대답요약 자리다.

1. 트리거 턴(PERSPECTIVE 즉발 가능 — M7) → 다리 대사 + `미션시작`. 팝업이 열리며
   intro 고정 대사 재생, 친구 카드 4장 표시.
2. 카드 선택 → events(`friend_select`) → ask 고정 대사.
3. 아이 대답 → 미션 턴. SHORT/UNCLEAR 이면 그 친구의 reask 로 1회 되묻기(M9).
   정상이면 요약·감탄 대사 + 카드 취소선 연출.
4. 더 도울지 → events(`more`): yes 면 `more_pick` 과 함께 2로(도운 친구 ✓),
   no 거나 4명 모두면 done → complete.
5. 종료 요약 + closing 재생 → 요소 평가 → 씬 이어가기/닫기.

도울 친구 최소 1명(현행 유지). 팝업 뒤로가기(`onQuit`)는 시도를 `abandoned` 로 기록하고
대화로 복귀 — 트리거 조건이 남아 있으므로 다음 턴에 다시 발동될 수 있다.

## 9. LLM 재료와 경계 — 프롬프트 2벌 신설

폴더 두 파일 체제(`prompts/<이름>/보낼것.md` + `해설.md`)를 따른다. **분석 프롬프트는
신설하지 않는다** — 씬의 요소 기준이 재료에 실리므로 기존 `analysis` 가 그대로 맞는다.

### `prompts/mission_reply` — 미션 턴 대사 (아이대답요약)

```jsonc
// 재료(user JSON)
{ "character": { "name": "…", "persona": "…", "speech_style": "…", "guidance_style": "…", "forbidden": [] },
  "scene":     { "conflict": "…", "stance": "…" },
  "mission":   { "goal": "…", "step": "use", "question": "…", "selection": "소쿠리" },
  "mission_said_so_far": [ { "speaker": "…", "text": "…" } ],
  "latest":    { "child_utterance": "…", "main_point": "…" },
  "direction": { "kind": "summary_reply" | "bridge_into_mission" } }
```

출력: 캐릭터 말투 한두 문장 — 아이 말의 요지를 되짚고(요약) 감탄·반응을 얹는다.
`bridge_into_mission` 이면 되짚은 뒤 미션 질문으로 자연스럽게 넘긴다.

### `prompts/mission_summary` — 종료 요약

```jsonc
// 재료(user JSON)
{ "character": { "…": "…" }, "mission": { "goal": "…", "selections": [] },
  "mission_dialogue": [ "…전체…" ],
  "guidance": { "remaining_worry": "배가 떨어져서 다 깨지면 어쩌나…" } } // 없으면 null
```

출력: 미션에서 아이가 정한 것(무엇으로·어떻게·뭐라고 부탁)을 캐릭터 말투로 되짚는
1~2문장. `remaining_worry` 가 있으면 그 걱정을 묻는 질문으로 끝낸다.

### 경계 규칙 — 기존 심판과 같은 결

- 정답 판정 금지("맞았어/틀렸어") — 미션1은 어느 소품이든 정답이다(현행 원칙 승계).
- 요소 코드·명칭 노출 금지, 새 설정 발명 금지 — 기존 캐릭터 경계 그대로.
- 호출 기록: `purpose='mission_reply'/'mission_summary'` 로 `llm_calls` 에, 실패도 남긴다.
- 프롬프트 이름 목록 검사(`tests/prompts.test.ts`)에 두 폴더를 추가해야 초록이 된다.

고정 문구 폴백으로 떨어진다 — 머지 시 반드시 맞출 것.

## 11. 수용 기준

1. 대화3에서 SOLUTION 이 감지된 턴의 응답에 `미션시작` 과 다리 대사가 실리고
   `mission_sessions` 행이 생긴다. SOLUTION 없이도 아이 턴 2회면 발동한다.
2. 대화4는 첫 대답이 PERSPECTIVE 면 1턴 만에 발동한다(M7).
3. 미션 턴을 돌면 `mission_messages` 에 아이·캐릭터 행과 분석 jsonb 가 쌓이고,
   `accumulated_elements` 에 요소가 합산되며 **씬 턴 수는 불변**이다.
4. SHORT/UNCLEAR 첫 시도는 되묻기 대사가 오고(두 미션 모두), 두 번째는 그대로 진행한다.
5. complete 후 `messages` 에 요약 캐릭터 행이 1개 생기고, 요소 충족이면 같은 요청에서
   씬이 닫히며(`GOAL_MET`) 다음 씬 여는 말이 저장돼 있다. `decide()`·`turn_conditions`
   경로는 타지 않는다.
6. 미션 경유로 씬이 닫히면 앱이 답변 컷을 건너뛰어 닫는 말이 한 번만 들린다(M6).
7. 미션 도중 껐다 켜면 세션 열기 응답에 새 시도가 실리고 이전 시도는 `abandoned`,
   합산된 요소는 남아 있다.
8. 미션 진행 중 일반 턴은 409 `MISSION_IN_PROGRESS`. complete 두 번은 같은 요약.
9. 미션 없는 씬(대화1·2)의 동작은 바이트 하나 안 바뀐다.
