## ⓪ 이게 무슨 기능인가

6~9세 아이가 옛이야기(「방귀 뀌는 며느리」) 속 캐릭터와 **말로 대화하는** 앱이다.
아이가 한 말을 LLM 이 읽고 사고 요소 8종을 찾아 기록한다. **활동 한 건이 끝나면 그
기록으로 보호자에게 보여 줄 리포트 한 장을 만든다** — 이 기능이다.

리포트는 두 조각이다. **숫자**(`metrics`)는 규칙이 세고, **문장**(`narrative`)은 LLM 이
쓴다. 그래서 LLM 이 실패해도 숫자가 담긴 리포트는 남는다.

⑴ 을 권한다 — 발화 3건에 오각형을 그리는 것 자체가 무리다.

## ③ 알고 있어야 할 것

### 🔴 인용은 **글자가 아니라 id 로** 오간다 — 이 설계의 핵심

LLM 이 없는 발화를 지어내 따옴표에 넣는 것을 막는 장치다. LLM 은 `quote_message_id` 만
고르고, `src/report/engine/verify.ts` 가 실제 발화 목록과 대조해 없으면 버린다.

**실물에서 작동한다.** 12장을 만들 때 아이10 에서 LLM 이 인용 id 를 `m1`·`m2`·`m3` 으로
**지어내** 이야기 질문 셋이 통째로 버려졌고, 아이8 2회차에서는 8요소가 아닌
`EMPOWERMENT` 를 지어내 한 건이 버려졌다.

⚠️ 우회로가 하나 있었다 — **자유 문장 칸**(`did_well`·`highlight.why` 등)은 대조하지
않는다. 2026-08-15 에 `A-NOQUOTE`·`G-NOQUOTE` 로 막았다. **낱말 하나를 감싸는 작은따옴표는
일부러 살렸다** — 화면이 어휘 팁에서 처음 나오는 작은따옴표를 파랗게 칠한다.

### 🔴 「한 편만 실패」는 살린다

문장 LLM 은 **두 편**이다. 한 편만 실패하면 `narrative` 가 `null` 이 되는 게 아니라
**실패한 편의 칸만 빈 글자(`''`)로** 온다.

| | `status` | `narrative` |
|---|---|---|
| 둘 다 성공 / **한 편만 실패** | `complete` | 실패한 편의 칸만 빔 |
| 둘 다 실패 | `metrics_only` | `null` |

⚠️ 화면이 `??` 로 받으면 안내 문구 대신 **빈 줄**이 그려진다. `src/lib/report.ts` 의
`textOr()` 가 막는 자리다. 검사 셋이 이것을 지킨다.

### 🔴 DB 는 로컬과 팀을 갈라 쓴다

- **검사(`vitest`)는 로컬 도커 `gq-pg`** — `postgresql://postgres:gqlocal@127.0.0.1:5432/goodquestion_ts`
  ```bash
  DATABASE_URL="postgresql://postgres:gqlocal@127.0.0.1:5432/goodquestion_ts" npx vitest run tests/report-metrics.test.ts
  ```
  본선 `.env.local` 은 팀 라이브를 가리켜서 그냥 돌리면 가드가 막는다(막는 것이 맞다).
- **실제 데이터는 팀 Supabase** — 목데이터·리포트가 거기 있다.
- ⛔ **`drizzle-kit push` 를 어떤 이유로도 치지 마라.** 선언에 없는 표를 지운다.
- ⛔ 저쪽 표 `reports`·`wordbook`·`children` 을 우리 드리즐 선언에 넣지 마라.

### 🔴 제미나이 키 셋을 병렬로 쓸 때

`buildChain` 은 `preferred_gemini_key` 를 줘도 **나머지 두 키와 앤트로픽 칸을 뒤에 붙인다.**
그래서 **환경변수로 키를 하나만 보이게** 하고 한 건이라도 부르기 전에 **체인이 한 칸인지
단언한다** (`seed-report-mock.ts` 의 `키_하나만_보이게()` · `체인이_한_칸인가()`).

⚠️ **리포트 생성은 샤드로 가르면 안 된다** — 활동이 여럿인 아이(태민 3건)의 「새 낱말」이
`child_words` 누적 순서에 걸려 있다.

### 그 밖에 걸리는 것

- **장면 이름표가 「장면 3」까지만 나온다.** 명세 예시는 「장면 3 · 들켜버린 큰 방귀」인데
  **장면 이름을 담을 칸이 DB 에 아예 없다.** 코드는 알고 있고 이름을 지어내지 않는다.
  이름을 붙이려면 별도 작업이 필요하다.
- **미션 발화의 이름표는 「미션 · 배 따기」 꼴**이다 (M7 확정). 화면이 「장면 N ·」 꼴만
  온다고 가정하면 깨진다.
- **보호자 잠금이 뚫려 있다** — `src/components/mypage/parent-report-card.tsx` 의 4자리
  확인이 **아무 숫자나 통과**한다. 리포트에 아이 발화 원문이 실리므로 실서비스 전에
  막아야 한다. 저장 자리를 만들려면 팀 레포 `parents` 표를 고쳐야 해 협의가 필요하다.
- **`--metrics` 로 숫자만 0회 비용으로 볼 수 있다** — `npx tsx src/llm/db/seed-report-mock.ts --metrics`

## ④ 확정된 결정 가운데 되짚을 것

- **축 점수는 감지된 발화 수 그대로** (R17). 정규화는 화면이 그 활동 안에서만 한다.
- **상호작용 = 질문 + 되묻기 회복 + soft-cue 응답** (M1, 2026-08-15 실측으로 확정).
  셋째 항이 없으면 **잘 답한 아이가 0점**이 된다. 명세 4.2 에 실측 표가 있다.
- **「요구 요소 대비 충족률」로 축을 매기지 마라** — 이 이야기의 required_elements 에
  `EMOTION`·`DECISION` 이 없어 감정 표현이 항상 0이 된다.
- **`child_words` 누적은 리포트 저장 뒤에** — 먼저 넣으면 「다시 만들기」의 새 낱말이 0이 된다.
- **`src/report/types.ts` 가 공유 계약이다.** 갈래에서 고치지 말고 본선에 보고한다.
