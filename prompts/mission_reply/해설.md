# 미션 턴 대사 프롬프트 (아이대답요약) — 해설

> ⛔ **이 파일은 LLM 에 한 글자도 안 간다.** 나가는 것은 옆의 `보낼것.md` 뿐이다.
>
> 규칙 한 덩이에 붙는 `[R-…]` 가 두 파일을 잇는다 — **같은 태그가 양쪽에 다 있어야
> 한다.** `tests/prompts.test.ts` 가 짝을 센다. 관리 규칙 전체는 `prompts/README.md`.
>
> 정본: `docs/미션_명세.md` 9절 (이슈 #18 · 확정 결정 M2). 캐릭터 프롬프트
> (`prompts/character`)의 언어·구조(영어 본문·한국어 출력)와 경계 규칙 결을 따랐다.

---

캐릭터 LLM 을 미션 턴에도 그대로 태우는 자리다(M2 — 별도 요약 엔진을 만들지 않는다).
미션 팝업 안에서 아이가 말하면, 분석(기존 `analysis` 재사용)의 요지와 함께 이 프롬프트가
**아이 말을 되짚는 캐릭터 대사 한 마디**를 만든다. 미션2에서 시안 04가 비워 뒀던
「며느리가 아이 말에 감탄하는 컷」이 바로 이 대사의 자리다.

`direction.kind` 로 두 자리를 겸한다:

- `summary_reply` — 미션 턴의 아이대답요약 (명세 7절 C 의 `dialogue`).
- `bridge_into_mission` — 트리거 턴의 다리 대사 (명세 7절 A). 고정 도입 문구가 아이
  말과 어긋나는 문제를 피하려고 생성으로 한다.

## 받는 것

user 본문은 언제나 재료 JSON 한 덩이다 (`buildMissionReplyMaterial()` —
`src/llm/engine/mission.ts`). 프롬프트는 그 글자를 한 번도 안 본다.

| 열쇠 | 무엇 |
| --- | --- |
| `character` | `name` · `persona` · `speech_style` · `guidance_style` · `forbidden` — 캐릭터 재료와 같은 다섯 |
| `scene` | `conflict` · `stance` |
| `mission` | `goal`(미션 목적 한 문장) · `step`(지금 스텝) · `question`(그 스텝의 고정 질문) · `selection`(고른 소품·카드 이름). 다리 대사 시점엔 스텝이 없어 빈칸 |
| `mission_said_so_far` | 이 미션 안에서 오간 말. 이번 발화는 빼고 온다 |
| `latest` | `child_utterance` · `main_point`(분석 요지) |
| `direction` | `kind` — `summary_reply` 또는 `bridge_into_mission` |

## 태그별 해설

### `[R-SUMM]` 되짚기가 이 대사의 본체다
「아이대답요약」이라는 이름 그대로다. 미션 응답 컷이 이 대사 하나뿐이라, 아이가 들은
자기 생각이 곧 보상이 된다. 📄 `docs/미션_명세.md` 9절 「아이 말의 요지를 되짚고(요약)
감탄·반응을 얹는다」.

### `[R-BRIDGE]` 다리 대사 — 되짚고 나서 미션으로 향한다
📄 `docs/미션_명세.md` 7절 A 「아이 제안을 되짚고 미션 질문으로 연결한다」. 선택지를
나열하지 않는 이유: 소품·카드는 바로 다음에 팝업이 화면으로 보여 준다.

### `[R-ASSAID]` 아이가 안 한 말을 보태지 않는다
요약에 방법·이유를 보태면 캐릭터가 아이 대신 답한 것이 된다 — 캐릭터 프롬프트의
「아이 대신 답하지 않는다」와 같은 선을 미션판으로 옮긴 것이다.

### `[R-NOGRADE]` 정답 판정 금지
미션1은 **어느 소품이든 정답**이다(현행 원칙 승계). "맞았어/틀렸어"는 물론, 채점처럼
들리는 칭찬도 막는다. 📄 `docs/미션_명세.md` 9절 경계 규칙.

### `[R-NOASK]` 고정 대사를 대신 말하지 않는다
스텝 질문(`config.steps[].ask`)·되묻기·closing 은 전부 config 고정 대사이고 앱이 따로
재생한다(명세 7절 B·C 의 `fixed_line`). 생성 대사가 같은 질문을 먼저 말하면 두 번
들린다 — M6(닫는 말은 한 번)과 같은 종류의 중복 방지다.

### `[R-NOTEACH]` · `[R-NOINVENT]`
기존 캐릭터 경계 그대로 (요소 코드·명칭 노출 금지, 새 설정 발명 금지).
📄 `docs/미션_명세.md` 9절 「경계 규칙 — 기존 심판과 같은 결」.

### `[R-SHORT]` 1~2문장
미션 팝업의 대화 패널은 짧다. 캐릭터 프롬프트의 C-SHORT 와 같은 기준이다
(태그 표기를 그대로 적으면 짝 검사가 이 파일의 태그로 세므로 괄호 없이 쓴다).

## 프롬프트에서 뺀 것과 그 이유

| 뺀 것 | 왜 |
| --- | --- |
| `remaining_worry` · 유도 지시 | 미션 턴은 유도하지 않는다(M3 — 유도 카운터 불변). 부족 요소는 미션 뒤 유도 대화가 맡고, 걱정 한 줄은 종료 요약(`prompts/mission_summary` 의 `guidance`)에만 실린다 |
| `story_so_far` · 본 대화 `said_so_far` | 명세 9절 재료에 없다. 미션은 팝업 안의 짧은 구간이라 미션 안에서 오간 말(`mission_said_so_far`)이면 충분하고, 토큰을 아낀다 |
| `scene_goal` | 캐릭터 재료와 같은 이유 — 읽으면 아이 대신 그 문장을 말해 버린다 |
| `response_mode` · `reaction_key` | 미션 턴에는 모드가 없다. 갈림은 `direction.kind` 둘뿐이다 |
