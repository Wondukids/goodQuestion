# `prompts/` — LLM 에 보내는 지시문의 정본

이 폴더는 **대화 엔진이 LLM(대규모 언어 모델)에게 보내는 지시문**이 사는 곳이다.
아이가 옛이야기 캐릭터에게 말을 걸면, 그 말을 읽고 무슨 생각이 담겼는지 뽑는 LLM 과
캐릭터의 다음 대사를 짓는 LLM 이 각각 한 번씩 불린다. 그 둘에게 「너는 무엇이고 무엇을
하면 안 되는가」를 적어 주는 글이 여기 `*.md` 파일들이다.

파일 하나가 층이 둘이다 — **사람이 읽는 한글 층**과 **LLM 에 실제로 나가는 영어 층**.
`<!-- 보내는 것 시작 -->` / `<!-- 보내는 것 끝 -->` 표식이 그 경계이고,
`sendableBody()`(`src/llm/prompts/parse.ts:74-77`)가 표식 안쪽만 오려서 보낸다.

이 문서는 **프롬프트를 고치거나 새로 쓸 때 지켜야 할 규율**을 모은 것이다.

> ⚠️ **근거에 관하여.** 이 폴더의 `*.md` 파일 본문과 `src/` 의 여러 주석은
> `CLAUDE.md 경계 N` · `docs/설계/…` · `docs/기준/…` · `notes/issues/…` · `결정 NN` 같은
> 문서를 인용한다. **그 문서들은 이 레포에 없다** — 파이썬 원본 레포에만 있던 것이고
> 이식할 때 따라오지 않았다. 이 README 는 그런 인용을 하지 않는다.
> 여기서 근거로 대는 것은 **이 레포에 실제로 있는 파일**(소스 경로+줄번호 · 검사 파일 ·
> DB 스키마 · SQL)뿐이다.

## 0. 지금 이 폴더에 있는 것

```
prompts/
  analysis.md                    두 층 (한글 + 영어)
  character.md                   두 층 (한글 + 영어)
  child.md                       두 층 (한글 + 영어)
  judge_gave_away_element.md     한 층 (한국어만, 통째로 나간다)
  judge_guided_toward_target.md  한 층
  judge_invented_setting.md      한 층
```

파일이 여섯 개라는 것과 이름 목록은 `tests/prompts.test.ts:59-64` 가 **정확히 일치**로
검사한다. 파일을 늘리거나 지우면 그 검사가 먼저 빨개진다.

## 1. 정본은 파일이다

🔴 **`prompts/*.md` 가 정본이다.** 다른 어떤 자리도 이 파일을 이기지 못한다.

관리자 화면에 프롬프트 작업대(`/prompt-lab`)가 있고, 거기서 고친 본문은 DB 표
`experiment_prompts` 에 들어간다. 그것은 **한 회차짜리 실험판**이다. 마음에 드는 판이
나왔으면 **사람이 손으로 이 폴더의 md 에 옮겨 적는다.**

⛔ **DB 에서 파일로 돌아가는 화살표는 없다.** 화면도, 서비스 층도, 리포 층도 파일을
쓰지 않는다. 자동으로 반영되기를 기다리지 마라 — 옮기지 않으면 다음 회차는 정본으로 돈다.

### 이 경계를 검사가 두 가지로 지킨다

`tests/prompt-lab.test.ts` 가 하나로는 새는 자리가 있어 둘을 겹쳐 둔다.

| | 어떻게 | 무엇을 잡나 |
| --- | --- | --- |
| ① 해시 대조 | 저장·조회 길을 다 지난 뒤 `prompts/` 안 모든 `*.md` 의 sha256 + mtime 이 그대로인가 (`tests/prompt-lab.test.ts:83-92`, 쓰는 검사는 `:360-382`) | **실제로** 파일에 손댄 코드 |
| ② 소스 훑기 | 작업대의 네 자리 소스에 파일 쓰기 API 이름이 한 글자라도 들어왔나 (`tests/prompt-lab.test.ts:103-144`) | 아직 안 불리는 길 · 앞으로 들어올 길 |

②가 훑는 네 파일은 `src/app/(admin)/prompt-lab/page.tsx` · `.../actions.ts` ·
`src/llm/service/prompt-lab.ts` · `src/llm/repo/prompt-lab.ts` 이고, 금지어는
`writeFile` · `writeFileSync` · `appendFile` · `appendFileSync` · `createWriteStream` ·
`truncate` · `unlink` · `rmSync` · `renameSync` · `copyFile` · `openSync` · `mkdirSync` ·
`child_process` 열셋이다. **주석에 이름을 적어도 빨개진다** — 「없다」를 글자로 세는
검사라 그렇다.

### 정본 md 는 검사도 안 건드린다

`tests/prompts.test.ts` 는 가짜 md 를 만들어 통과시키지 않는다. **정본 여섯 개를 그대로
파싱한다** — 「md 를 고치면 코드가 따라온다」는 성질은 진짜 파일로만 확인되기 때문이다.
읽고 파싱한 뒤에도 파일이 그대로인지까지 본다(`tests/prompts.test.ts:224-234`).

## 2. 두 층 — 무엇을 어느 쪽에 쓰나

`sendableBody()` 는 **자르기만 한다.** 두 층의 뜻이 어긋났는지는 보지 못한다.
그래서 「무엇을 어느 쪽에 쓰는가」를 사람이 지켜야 한다.

| | 나가는 쪽 (`<!-- 보내는 것 시작 -->` 안) | 사람 쪽 (표식 바깥) |
| --- | --- | --- |
| 지시 본문 | ⭕ 여기 | |
| 규칙 태그(`[E-…]` 등) | ⭕ 여기 | ⭕ **같은 태그가 여기도** |
| 판정 예시 (⭕/❌ 발화) | ⭕ 여기 | |
| 출력 규격 (JSON 모양 · 「한 마디만」) | ⭕ 여기 | |
| 왜 이렇게 정했나 | | ⭕ 여기 |
| 출처 인용 (📄 ✏️ 🌐 📏) | | ⭕ 여기 |
| 「프롬프트에서 뺀 것과 그 이유」 | | ⭕ 여기 |
| 재료 열쇠 표 (무슨 값이 오는가) | | ⭕ 여기 |
| 검수 이력 · 실측 숫자 | | ⭕ 여기 |

**왜 가르나.** 사람 쪽 글은 모델에게 쓸모가 없는데 토큰은 그대로 먹는다. 실측하면
`analysis.md` 는 전체 16,597자 중 6,255자(38%)만, `character.md` 는 14,488자 중
6,513자(45%)만, `child.md` 는 4,629자 중 1,931자(42%)만 나간다.
나머지 절반 넘는 글자가 사람 몫이다.

> 🔴 **⚠️ 윈도우 작업 트리에서는 이 자르기가 지금 작동하지 않는다** (2026-08-14 확인).
>
> `sendableBody()` 의 정규식(`src/llm/prompts/parse.ts:50`)이 `-->` 뒤에 **`\n` 리터럴**을
> 요구한다. 그런데 `core.autocrlf=true` 인 윈도우에서는 체크아웃할 때 줄 끝이 `\r\n` 이
> 되어 `-->` 뒤가 `\r` 이라 매칭이 실패한다. 그러면 「표식이 없으면 통째로」 규칙이 발동해
> **파일 전체가 나간다** — 위 38%가 100%가 된다.
>
> **깃 오브젝트에는 LF 로 저장돼 있다**(`git ls-files --eol prompts/` → `i/lf w/crlf`).
> 그래서 **리눅스·CI·배포 환경에서는 정상으로 돈다.** 즉 프로덕션 장애가 아니라
> **윈도우 개발 트리 한정** 문제다.
>
> ⚠️ 다만 **윈도우에서 잰 골든셋 점수와 `tools/*.ts` 결과는 프로덕션 조건의 값이 아니다.**
> 그때 모델은 한글 층까지 다 읽었다.
>
> 고치는 길 둘 — ① 레포에 `.gitattributes` 로 LF 를 못박고 작업 트리를 다시 꺼낸다
> ② 정규식을 `-->\r?\n` 으로 고친다. **둘 다 해 두는 것이 정석이다** — 전자는 저장소
> 규율이고 후자는 입력 방어다. 후자만 있으면 지문(5절)이 OS 마다 갈리는 문제가 남는다.

⚠️ **표식이 없으면 통째로 나간다**(`src/llm/prompts/parse.ts:74-77`). 이건 버그가 아니라
실험 프롬프트를 위한 규칙이다 — 작업대에서 사람이 써 넣은 본문에는 층이 없고, 거기서
잘라내려 들면 사람이 쓴 프롬프트가 통째로 사라진다. **한 글자도 못 찾겠으면 다 보내는
쪽이 안전하다.** 그래서 심판 프롬프트 셋(층이 하나)도 통째로 나간다
(`tests/prompts.test.ts:173-176` 이 그걸 못박는다).

### 「받는 것」 절 — 지금 이렇고, 앞으로 이렇게 된다

**지금.** `analysis.md` · `character.md` · `child.md` 는 `## 받는 것` 절 뒤에 코드블록을
하나 두고, `materialTemplate()`(`src/llm/prompts/parse.ts:99-114`)이 그 블록을 정규식으로
뽑아 **틀**로 쓴다. 그 안의 `{analysis_material}` 같은 자리표시자를 `fill()` 이 채워
user 본문을 만든다.

**앞으로 (2026-08-14 사람 결정).** 이 파싱을 걷어낸다. 파일마다 자리표시자가 정확히
하나뿐이라(`tests/prompts.test.ts:78-82` 가 그걸 단언한다) 틀에서 지킬 목록이 없다.
`user = materialJson(재료)` 한 줄로 끝낸다.

- 재료가 실제로 무슨 열쇠를 갖는지는 **코드가 정한다**
  (`buildAnalysisMaterial()` — `src/llm/engine/material.ts:183-218`,
  `buildCharacterMaterialBundle()` — `:253-304`).
- 그러니 md 의 **재료 열쇠 표는 사람이 읽는 쪽에 남는다.** 그건 문서이지 틀이 아니다.

⚠️ 이관 전까지는 `## 받는 것` 절과 코드블록을 **지우지 마라.** 지우면
`materialTemplate()` 이 「「받는 것」 절이 없다」로 터진다.

## 3. 태그 규약 — `[E-…]` · `[C-…]` · `[K-…]`

규칙 한 덩이에 태그 하나를 붙이고, **두 층에 같은 태그를 쓴다.** 사람이 두 층을 나란히
놓고 「이 규칙이 저쪽엔 뭐라고 적혔나」를 눈으로 찾을 수 있게 하는 손잡이다.

| 머리 | 어느 프롬프트 | 지금 개수 |
| --- | --- | --- |
| `[E-…]` | `analysis.md` (Element / 분석) | 13 |
| `[C-…]` | `character.md` (Character) | 14 |
| `[K-…]` | `child.md` (Kid) | 5 |

**32쌍이 지금 정확히 맞는다.** 세 파일 모두 안쪽 태그 집합과 바깥쪽 태그 집합이
같다(2026-08-14 실측). 예를 들어 `analysis.md` 는 `E-BARE` · `E-EMOTION` · `E-EMPATHY` ·
`E-INTENT` · `E-MULTI` · `E-NOCRIT` · `E-REASON` · `E-REQUEST` · `E-RESULT` · `E-SHORT` ·
`E-SOLUTION` · `E-VERBATIM` · `E-YOUNG` 열셋이 양쪽에 다 있다.

> 🔴 **⚠️ 이 짝을 지키는 자동 검사가 이 레포에 없다.**
> 세 md 의 머리말은 「한쪽에만 있으면 `tests/test_프롬프트_두층.py` 가 잡는다」고 적어
> 두었는데, **그 검사는 파이썬 원본 레포의 것이고 여기 없다.** `tests/` 를 훑어도
> `[E-`·`[C-`·`[K-` 를 세는 검사가 하나도 없다. 그러니 **지금은 사람이 지킨다.**
> 규칙을 하나 더할 때 한쪽에만 적으면 아무도 안 알려 준다.

⚠️ 그리고 검사를 만들어도 잡히지 않는 것이 있다 — **「태그는 양쪽에 있는데 뜻이
어긋난 것」.** 그건 두 층을 나란히 놓고 사람이 읽어야 한다.

## 4. 언어 규칙 — 기준은 언어가 아니라 「나가는가」다

| 프롬프트 | 나가는 쪽의 언어 |
| --- | --- |
| `analysis.md` · `character.md` · `child.md` | **영어** |
| `judge_gave_away_element.md` · `judge_guided_toward_target.md` · `judge_invented_setting.md` | **한국어** |

**분석·캐릭터·아이가 영어인 이유는 토큰 절약이다.** 한글 한 글자가 영어보다 토큰을 더
먹는다. 지시문은 길고 매 턴 나가므로 여기서 아끼는 것이 크다.

**심판 셋이 한국어인 이유는 판정 대상이 한국어이기 때문이다.** 심판은 캐릭터가 만든
한국어 대사를 읽고 「경계를 넘었나」를 매기고, 판정 근거로 **대사에서 글자를 그대로
잘라 내야** 한다(`src/llm/judge.ts:429` 가 근거가 대사 안에 있는지 대조하고, 없으면 그
판정을 버린다). 판정 어휘 자체도 한국어다 — `{"판정": "위반"|"통과"|"판정불가", …}`.
그 프롬프트는 층이 하나라 **파일 전체가 그대로 나간다.**

### 예시 발화는 영어 프롬프트 안에서도 한국어다

판정 대상이 한국어 발화이므로 예시를 번역하면 예시가 아니게 된다. 실제로
`analysis.md` 의 영어 층 안에는 한글이 208자 들어 있고(`"다 같이 도와줘야 해요"` ·
`"며느리한테 화내지 말고 미안하다고 말해 주세요"` 같은 판정 예시와 `-니까` · `-어서`
같은 어미), `child.md` 영어 층에도 「어… 그게…」·「몰라요」·`초1`·`초3` 이 그대로 있다.

`character.md` 영어 층에는 한글이 0자다. 예시 발화를 안 쓰고, 대신 첫 줄이
`Write your ONE next line, in Korean.` 으로 출력 언어를 못박는다.

**즉 판단 기준은 「이 글자가 영어냐 한국어냐」가 아니라 「이 글자가 나가느냐」다.**
나가는 쪽이면 토큰을 아끼는 말로, 안 나가는 쪽이면 사람이 읽기 좋은 한국어로 쓴다.

## 5. 고칠 때 절차

### 캐시가 없다 — 고치면 바로 반영된다

`read()`(`src/llm/prompts/render.ts:74-81`)는 **부를 때마다 디스크를 읽는다.** 모듈
전역에 담아 두는 것이 없다(`tests/prompt-lab.test.ts:159-179` 가 그걸 검사한다).

⚠️ 그러니 **배포도 재시작도 필요 없고, 되돌릴 배포 경로도 없다.** md 를 저장하는 순간
다음 LLM 호출부터 새 글자가 나간다. 돌고 있는 회차 한가운데서 고치면 **같은 회차의
앞턴과 뒷턴이 다른 프롬프트로 돈다.**

### 그래서 이 차례로 고친다

1. **고치기 전에 골든셋 기준선을 찍는다.** (`/goldenset` 화면 · `src/llm/service/goldenset.ts`)
2. md 를 고친다.
3. **다시 잰다.** 같은 정답지 파일로.
4. 점수가 떨어졌으면 되돌린다. 올랐으면 무엇을 고쳐서 올랐는지 사람 쪽 층에 적는다.

### ⚠️ 지문이 바뀌면 이전 판과의 비교가 끊긴다

골든셋 한 판을 저장할 때 `analysis.md` **파일 전체의 sha256** 을 `prompt_digest` 로 함께
박제한다(`promptDigest()` — `src/llm/service/goldenset.ts:201-203`, 저장은 `:472`,
칸은 `src/llm/db/schema.ts` 의 `goldenset_runs`).

**보낼 층이 아니라 파일 통째다.** 사람이 한글 층만 고쳐도 지문이 바뀐다 — 그래야
「그때 그 프롬프트였다」를 말할 수 있다. 뒤집으면, **한글 층 오타 하나만 고쳐도 이전
판들과 지문이 갈린다.** 여러 판을 견주려면 재는 동안 파일을 건드리지 않는 편이 낫다.

> 🔴 **⚠️ 지금 지문은 OS 마다 다르다** (2026-08-14 확인).
>
> `fileDigest()` 는 **원문 바이트**의 sha256 이라 줄 끝의 `\r` 이 그대로 들어간다.
> 같은 커밋인데 윈도우(CRLF)와 리눅스(LF)의 지문이 파일 여섯 개 전부 다르다.
> 예: `analysis.md` 가 윈도우 `93dc47db…` · 리눅스 `307600ac…`.
>
> ⚠️ **정답지도 같다.** `goldenset/*.jsonl` 에도 같은 함수를 쓴다
> (`src/llm/service/goldenset.ts:470`). 세 파일 모두 지문이 갈린다.
>
> **지문으로 판올림을 관리하려면 이것부터 고쳐야 한다** (위 2절의 `.gitattributes`).
> 고친 뒤에는 이전에 박제된 CRLF 지문들이 **어느 파일과도 매칭되지 않는다** —
> 과거 회차를 프롬프트와 잇고 싶으면 매핑 표를 따로 남겨야 한다.

> `runs.prompt_version`(`src/llm/db/schema.ts:480`)은 md 의 내용과 아무 상관이 없다.
> 회차를 열 때 사람이 붙이는 이름표일 뿐이고, 자동으로 안 바뀐다. 이것으로 「어느
> 프롬프트였나」를 알 수 있다고 믿지 마라.

## 6. 실험판의 경계

작업대에서 고친 본문에는 세 가지 울타리가 있다.

### ① 회차 하나에만 걸린다

`experiment_prompts` 의 기본키가 `(run_id, name)` 이다(`src/llm/db/schema.ts:717-730`,
`sql/003_admin.sql:167-173`). 읽을 때도 `run_id` 로만 읽으므로
**다른 회차로 새지 않는다**(`readExperimentPrompts()` — `src/llm/repo/prompt-lab.ts:33-43`,
검사는 `tests/prompt-lab.test.ts:384-400`).

같은 (회차, 이름)에 다시 저장하면 행이 늘지 않고 본문만 바뀐다.

### ② `analysis` 와 `character` 둘만 실험할 수 있다

이 제약이 **세 곳에 박혀 있다.** 한 곳만 고치면 나머지 둘이 막는다.

| 어디 | 무엇 |
| --- | --- |
| 리포 (코드) | `실험할_수_있는_이름 = ['analysis', 'character']` — `src/llm/repo/prompt-lab.ts:24`, 어기면 `src/llm/repo/prompt-lab.ts:57-59` 에서 `ValueError` |
| DB (CHECK) | `experiment_prompts_name_check CHECK (name IN ('analysis','character'))` — `src/llm/db/schema.ts:728`, `sql/003_admin.sql:171` |
| 화면 | 같은 목록으로 `editable` 을 정한다 — `src/llm/service/prompt-lab.ts:102`, 폼 검증은 `src/app/(admin)/prompt-lab/actions.ts:41` |

`child` 나 `judge_*` 를 저장하려 하면 화면에서도 저장 층에서도 막힌다
(`tests/prompt-lab.test.ts:432-445`).

### ③ 나가는 본문 하나만 대체한다

실험 본문은 **system 자리(보낼 층)를 통째로 갈아끼울 뿐**이다. 재료를 만드는 코드도,
출력 스키마도, 판정 규칙도 그대로다.

실험 본문에는 보통 표식이 없으므로 `sendableBody()` 가 통째로 돌려준다 — 사람이 쓴
그대로 나간다. 저장할 때도 다듬지 않는다(`src/llm/service/prompt-lab.ts:130-132`).
⛔ 빈 본문은 거절한다 — 빈 것을 저장하면 그 회차는 system 없이 도는데, 그게 실험인지
실수인지 나중에 못 가른다.

턴을 도는 길이 이 값을 집어 온다: `src/llm/service/step.ts:163-171` ·
`src/llm/service/run.ts:525`. 부르는 쪽이 본문을 명시로 넘기면 그것이 이긴다
(「안 주면 파일」 규칙은 `chooseBody()` 한 곳에만 있다 — `src/llm/prompts/render.ts:93-95`).

## 7. 프롬프트가 아닌 것 — 여기서 찾지 마라

### 장면별 값은 DB 시드에 산다

「이 장면에서 `EMOTION` 을 인정하려면 발화에 무엇이 있어야 하나」, 「이 장면에서
캐릭터는 어떤 입장이고 무슨 걱정이 남았나」는 **md 가 아니라 `story_scenes` 표**에 있다.

| 칸 | 무엇 | 어디 |
| --- | --- | --- |
| `element_criteria` | 요소마다의 이 장면 인정 기준 | `src/llm/db/schema.ts:214`, 값은 `src/llm/db/seed.ts:294`·`:345`·`:378`·`:412` |
| `remaining_worries` | 이 장면에서 캐릭터에게 남은 걱정 (요소별 한 문장) | `src/llm/db/schema.ts:199`, 값은 `src/llm/db/seed.ts:278` 부터 |
| `scene_stance` | 이 장면에서의 캐릭터 입장 | `src/llm/db/schema.ts:193`, 값은 `src/llm/db/seed.ts:274` 부터 |
| `guidance_style` · `forbidden` | 어떻게 유도하나 · 무엇을 말하지 않나 | `characters` 표 — `src/llm/db/schema.ts:133` 근처 |

md 는 **「그 값을 어떻게 쓰라」**만 적고, **값 자체는 시드가 갖는다.** 장면 하나의 판정이
이상하면 프롬프트가 아니라 시드를 먼저 보라.

⚠️ 캐릭터 프롬프트에 `scene_goal`(장면 학습 목표)은 **안 들어간다.** 읽으면 캐릭터가 아이
대신 그 문장을 말해 버린다. 안 넣는 것 셋은 `src/llm/engine/material.ts:235-251` 에 적혀 있다.

### 이 폴더 밖의 「프롬프트」들

이름이 프롬프트일 뿐, **이 규율 밖이다.** 두 층도 태그도 작업대도 적용되지 않는다.

- `src/lib/recommendations.ts:160-162` 의 `SYSTEM_PROMPT` — 아이 앱의 동화 추천 큐레이터.
  아이 앱 도메인(Supabase)이고 대화 엔진과 DB 도 다르다.
- TTS 의 `stylePrompt` — 읽어 주는 말투 연기 지시. `src/tts/server.ts:109-113`,
  값은 `src/stories/fart-bride/data.ts` · `script.ts` 에 대사마다 붙어 있다.

## 8. 여섯 파일 — 무엇이고, 어디까지 배선됐나

| 파일 | 무엇 | 엔진에 붙었나 |
| --- | --- | --- |
| `analysis.md` | 아이 발화를 읽고 의도·핵심·사고 요소를 JSON 으로 뽑는다 | ⭕ `src/llm/engine/analyze.ts:243` |
| `character.md` | 캐릭터의 다음 대사 한 마디를 짓는다 | ⭕ `src/llm/engine/character.ts:58` |
| `child.md` | **아이 역할 대역** (측정 전용, 제품 아님) | 🔴 **아직 안 돈다** — 아래를 볼 것 |
| `judge_gave_away_element.md` | 캐릭터가 아이 대신 답을 말해 버렸나 | ⭕ `src/llm/judge.ts:443-461` |
| `judge_guided_toward_target.md` | 캐릭터가 이번 턴의 과녁 쪽으로 유도했나 | ⭕ `src/llm/judge.ts:477` |
| `judge_invented_setting.md` | 캐릭터가 없는 설정을 지어냈나 | ⭕ `src/llm/judge.ts:515` |

심판 셋은 `boundaryChecks()`(`src/llm/judge.ts:572-590`)가 한 번에 부르고, 턴을 도는 길이
자동 채점을 켠 회차에서 그것을 부른다(`src/llm/service/turn.ts:609-614`).

> ⚠️ `tests/prompts.test.ts:37-40` 의 주석은 「TS 는 아직 `judge_guided_toward_target` 을
> 부르지 않는다」고 적어 두었는데 **그 주석은 낡았다.** `src/llm/judge.ts:477` 과
> `:586` 이 실제로 부른다.

### 🔴 `child.md` 는 정본이되 아직 안 돈다

**착각하기 쉬운 자리라 못박아 둔다.** 파일은 완성돼 있고, 파서 검사도 통과하고,
작업대 화면에도 뜬다. **그런데 이 프롬프트로 LLM 을 부르는 코드가 `src/` 어디에도 없다.**

- `child_material` 이라는 글자가 `src/` 전체에 **0곳**이다 (있는 곳은
  `prompts/child.md:30` 과 `tests/prompts.test.ts:32` 뿐).
- `src/llm/engine/` 에는 `analyze.ts` · `character.ts` · `material.ts` 셋뿐이고,
  아이 대역 엔진이 없다.
- `chooseBody('child', …)` 를 부르는 자리도 없다.

**그래서 회차를 돌려도 아이 대사는 이 프롬프트에서 나오지 않는다.** 지금 아이 발화는
사람이 넣거나 다른 경로에서 온다(`runs.default_utterance_source`).

**살려 둔다** (2026-08-14 사람 결정). 아이 역할 LLM 을 쓸 계획이 있고, 파일에 담긴 설계 —
특히 「일부러 **안** 주는 것」 표(`required_elements` · `element_criteria` ·
`guidance_target` · `remaining_worries` · `scene_goal` · 뒷이야기를 아이에게 안 준다) —
가 그때 다시 쓰인다. 정답을 알려 준 아이로 재면 「유도가 됐나」가 아니라 「아이가 정답을
봤나」를 재게 되기 때문이다. 지우면 그 판단이 같이 사라진다.

⚠️ `child.md` 는 **제품이 아니다.** 실제 서비스에서 아이는 사람이다. 이 프롬프트로 낸
「유도 성공률」은 사람 검수 전에 성과로 주장하지 말 것. 재는 것은 판 사이의 **차이**지
절댓값이 아니다.

## 9. 이관 예정 — 폴더 하나에 두 파일

> 🔴 **아직 안 옮겼다.** 지금 이 폴더에는 **평평한 `*.md` 여섯 개**만 있다.
> 아래 모양을 찾아 폴더를 열어 보면 없다. 이 절은 **앞으로의 규칙**이다.

곧 프롬프트 하나를 폴더 하나로 나눌 예정이다.

```
prompts/
  analysis/
    보낼것.md     ← LLM 에 나가는 것. 통째로 나간다 (표식이 필요 없어진다)
    해설.md       ← 사람이 읽는 것. 왜 이렇게 정했나 · 출처 · 재료 열쇠 표 · 검수 이력
  character/
    보낼것.md
    해설.md
  ...
```

**왜.** 지금은 한 파일 안에서 표식으로 가르는데, ①「어느 쪽에 쓰는 글인가」를 매번
사람이 판단해야 하고 ② 표식을 잘못 옮기면 사람 쪽 글이 통째로 LLM 에 실린다.
파일을 갈라 두면 **자리가 곧 규칙**이 된다.

이관 뒤에도 **위 2~4절의 분배는 그대로다.** 무엇을 어느 쪽에 쓰는가(2절), 태그를 두 쪽에
같이 다는 것(3절), 나가는 쪽만 토큰을 아끼는 것(4절)은 파일이 갈려도 같다.

이관할 때 함께 손봐야 할 자리 (지금 파일 이름과 표식을 아는 코드):

- `src/llm/prompts/render.ts:36` — 표식 파일 이름 `analysis.md` 로 `prompts/` 를 찾는다
- `src/llm/prompts/render.ts:76` — `prompts/<이름>.md` 로 경로를 만든다
- `src/llm/prompts/parse.ts:50` — `<!-- 보내는 것 시작/끝 -->` 정규식
- `src/llm/service/prompt-lab.ts:63-69` — `*.md` 파일 이름에서 프롬프트 이름을 뽑는다
- `src/llm/service/goldenset.ts:202` — `analysis.md` 의 지문을 뜬다
- `tests/prompts.test.ts` · `tests/prompt-lab.test.ts` — 둘 다 `*.md` 목록을 직접 훑는다

⚠️ **이관과 내용 고치기를 같은 걸음에 하지 마라.** 골든셋 점수가 흔들렸을 때
「자리를 옮겨서」인지 「글자를 고쳐서」인지 못 가른다.
