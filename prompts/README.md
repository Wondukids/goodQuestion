# `prompts/` — LLM 에 보내는 지시문의 정본

이 폴더는 **대화 엔진이 LLM(대규모 언어 모델)에게 보내는 지시문**이 사는 곳이다.
아이가 옛이야기 캐릭터에게 말을 걸면, 그 말을 읽고 무슨 생각이 담겼는지 뽑는 LLM 과
캐릭터의 다음 대사를 짓는 LLM 이 각각 한 번씩 불린다. 그 둘에게 「너는 무엇이고 무엇을
하면 안 되는가」를 적어 주는 글이 여기 있다.

**프롬프트 하나가 폴더 하나이고, 그 안에 파일이 둘이다.**

| 파일 | 무엇 | LLM 에 가나 |
| --- | --- | --- |
| `보낼것.md` | 지시 본문 · 규칙 태그 · 판정 예시 · 출력 규격 | ⭕ **이 파일이 곧 나가는 글자다** |
| `해설.md` | 왜 이렇게 정했나 · 출처 인용 · 검수 이력 · 재료 열쇠 표 | ❌ 한 글자도 안 간다 |

`read()`(`src/llm/prompts/render.ts`)가 `보낼것.md` 만 연다. **오리거나 다듬는 자리가
없다** — 파일이 곧 글자다.

> 2026-08-14 전에는 파일 하나 안에 두 층을 두고 `<!-- 보내는 것 시작 -->` 표식 사이를
> 정규식으로 오려 냈다. 그 정규식이 `-->` 뒤에 `\n` 리터럴을 요구해서 CRLF 로
> 체크아웃한 윈도우에서 매칭이 실패했고, 「표식이 없으면 통째로」 안전장치가 걸려
> **사람이 읽는 층까지 전부 LLM 에 나갔다.** 나눠 두면 그 종류의 버그가 날 자리가 없다.

이 문서는 **프롬프트를 고치거나 새로 쓸 때 지켜야 할 규율**을 모은 것이다.

> ⚠️ **근거에 관하여.** 이 폴더의 파일 본문과 `src/` 의 여러 주석은
> `CLAUDE.md 경계 N` · `docs/설계/…` · `docs/기준/…` · `notes/issues/…` · `결정 NN` 같은
> 문서를 인용한다. **그 문서들은 이 레포에 없다** — 파이썬 원본 레포에만 있던 것이고
> 이식할 때 따라오지 않았다. 이 README 는 그런 인용을 하지 않는다.
> 여기서 근거로 대는 것은 **이 레포에 실제로 있는 파일**(소스 경로+줄번호 · 검사 파일 ·
> DB 스키마 · SQL)뿐이다.

## 0. 지금 이 폴더에 있는 것

```
prompts/
  README.md                      ← 이 문서. 프롬프트가 아니다
  analysis/                      보낼것.md (영어) · 해설.md
  character/                     보낼것.md (영어) · 해설.md
  child/                         보낼것.md (영어) · 해설.md
  judge_gave_away_element/       보낼것.md (한국어) · 해설.md
  judge_guided_toward_target/    보낼것.md (한국어) · 해설.md
  judge_invented_setting/        보낼것.md (한국어) · 해설.md
  mission_reply/                 보낼것.md (영어) · 해설.md   ← 이슈 #18
  mission_summary/               보낼것.md (영어) · 해설.md   ← 이슈 #18
```

폴더가 여덟이라는 것과 이름 목록, 그리고 **폴더마다 두 파일이 다 있는지**를
`tests/prompts.test.ts` 가 검사한다. 늘리거나 지우면 그 검사가 먼저 빨개진다.

🔴 **폴더 이름을 바꾸지 마라.** `'analysis'`·`'character'` 는 실험판 표의 값이기도 해서
DB CHECK(`src/llm/db/schema.ts`)·리포(`src/llm/repo/prompt-lab.ts`)·폼 검증
(`src/app/(admin)/prompt-lab/actions.ts`) 세 곳에 못박혀 있다 (6절 ②).

## 1. 정본은 파일이다

🔴 **`prompts/<이름>/보낼것.md` 가 정본이다.** 다른 어떤 자리도 이 파일을 이기지 못한다.

관리자 화면에 프롬프트 작업대(`/prompt-lab`)가 있고, 거기서 고친 본문은 DB 표
`experiment_prompts` 에 들어간다. 그것은 **한 회차짜리 실험판**이다. 마음에 드는 판이
나왔으면 **사람이 손으로 그 폴더의 `보낼것.md` 에 옮겨 적는다.**

⛔ **DB 에서 파일로 돌아가는 화살표는 없다.** 화면도, 서비스 층도, 리포 층도 파일을
쓰지 않는다. 자동으로 반영되기를 기다리지 마라 — 옮기지 않으면 다음 회차는 정본으로 돈다.

### 이 경계를 검사가 두 가지로 지킨다

`tests/prompt-lab.test.ts` 가 하나로는 새는 자리가 있어 둘을 겹쳐 둔다.

| | 어떻게 | 무엇을 잡나 |
| --- | --- | --- |
| ① 해시 대조 | 저장·조회 길을 다 지난 뒤 `prompts/` 아래 **모든 md 열셋**(폴더 안까지)의 sha256 + mtime 이 그대로인가 | **실제로** 파일에 손댄 코드 |
| ② 소스 훑기 | 작업대의 네 자리 소스에 파일 쓰기 API 이름이 한 글자라도 들어왔나 | 아직 안 불리는 길 · 앞으로 들어올 길 |

②가 훑는 네 파일은 `src/app/(admin)/prompt-lab/page.tsx` · `.../actions.ts` ·
`src/llm/service/prompt-lab.ts` · `src/llm/repo/prompt-lab.ts` 이고, 금지어는
`writeFile` · `writeFileSync` · `appendFile` · `appendFileSync` · `createWriteStream` ·
`truncate` · `unlink` · `rmSync` · `renameSync` · `copyFile` · `openSync` · `mkdirSync` ·
`child_process` 열셋이다. **주석에 이름을 적어도 빨개진다** — 「없다」를 글자로 세는
검사라 그렇다.

### 정본 md 는 검사도 안 건드린다

`tests/prompts.test.ts` 는 가짜 md 를 만들어 통과시키지 않는다. **정본 여덟을 그대로
읽는다** — 「md 를 고치면 코드가 따라온다」는 성질은 진짜 파일로만 확인되기 때문이다.
열여섯 파일을 다 읽은 뒤에도 그대로인지까지 본다.

## 2. 두 파일 — 무엇을 어느 쪽에 쓰나

`보낼것.md` 는 **오리거나 다듬지 않고 통째로** system 으로 나간다. 그래서 여기 쓴 글자는
전부 모델이 읽고 토큰을 먹는다. 「무엇을 어느 쪽에 쓰는가」를 사람이 지켜야 한다.

| | `보낼것.md` | `해설.md` |
| --- | --- | --- |
| 지시 본문 | ⭕ | |
| 규칙 태그(`[E-…]` 등) | ⭕ | ⭕ **같은 태그가 여기도** |
| 판정 예시 (⭕/❌ 발화) | ⭕ | |
| 출력 규격 (JSON 모양 · 「한 마디만」) | ⭕ | |
| 왜 이렇게 정했나 | | ⭕ |
| 출처 인용 (📄 ✏️ 🌐 📏) | | ⭕ |
| 「프롬프트에서 뺀 것과 그 이유」 | | ⭕ |
| 재료 열쇠 표 (무슨 값이 오는가) | | ⭕ |
| 검수 이력 · 실측 숫자 | | ⭕ |

**왜 가르나.** 해설 쪽 글은 모델에게 쓸모가 없는데 토큰은 그대로 먹는다. 실측하면
`analysis` 는 16,597자 중 6,255자(38%)만, `character` 는 14,488자 중 6,513자(45%)만,
`child` 는 4,629자 중 1,931자(42%)만 나간다. **나머지 절반 넘는 글자가 사람 몫이다.**

### 재료는 프롬프트가 정하지 않는다

user 본문은 언제나 `materialJson(재료)` — **JSON 한 덩이**다. 무슨 열쇠가 들어가는지는
**코드가 정한다**(`buildAnalysisMaterial()` · `buildCharacterMaterialBundle()` —
`src/llm/engine/material.ts`). 프롬프트는 그 글자를 한 번도 안 본다.

⛔ 그러니 `보낼것.md` 에 `{child_utterance}` 같은 **자리표시자를 쓰지 마라.** 안 채워지고
글자 그대로 모델에게 나간다. 실험 프롬프트도 마찬가지다.

> 2026-08-14 전에는 md 의 「## 받는 것」 절 뒤 코드블록을 틀로 뽑아 자리표시자를 채웠다.
> 채울 자리가 파일마다 `{analysis_material}` 하나뿐이라 지킬 목록이 없어져 걷어냈다.
> 재료의 열쇠 표는 사람이 읽으라고 `해설.md` 에 남는다 — 그건 문서이지 틀이 아니다.

### ⚠️ 실험 프롬프트는 나가는 쪽만 대체한다

작업대에서 사람이 써 넣은 본문은 `보낼것.md` **자리에 통째로 들어간다.** 해설은 원래
안 나가므로 실험과 정본이 같은 저울에 오른다.

## 3. 태그 규약 — `[E-…]` · `[C-…]` · `[K-…]`

규칙 한 덩이에 태그 하나를 붙이고, **두 파일에 같은 태그를 쓴다.** 사람이 두 파일을
나란히 놓고 「이 규칙이 저쪽엔 뭐라고 적혔나」를 눈으로 찾을 수 있게 하는 손잡이다.

| 머리 | 어느 프롬프트 | 개수 |
| --- | --- | --- |
| `[E-…]` | `analysis` (Element / 분석) | 13 |
| `[C-…]` | `character` (Character) | 14 |
| `[K-…]` | `child` (Kid) | 5 |
| `[R-…]` | `mission_reply` (Reply / 아이대답요약) | 8 |
| `[S-…]` | `mission_summary` (Summary / 종료 요약) | 7 |

**47쌍이 맞는다.** 예를 들어 `analysis` 는 `E-BARE` · `E-EMOTION` · `E-EMPATHY` ·
`E-INTENT` · `E-MULTI` · `E-NOCRIT` · `E-REASON` · `E-REQUEST` · `E-RESULT` · `E-SHORT` ·
`E-SOLUTION` · `E-VERBATIM` · `E-YOUNG` 열셋이 양쪽에 다 있다.

### 검사가 지킨다 (`tests/prompts.test.ts`)

| | 무엇을 보나 |
| --- | --- |
| ① 태그 짝 | 두 파일의 태그 집합이 같은가. **한쪽에만 있는 것을 이름까지 찍어** 알려 준다 |
| ② 인용 누출 | `보낼것.md` 에 `docs/`·`CLAUDE.md`·`notes/`·`이슈 #`·📄·✏️ 가 없는가 |
| ③ 경로 봉인 | 해설 파일 이름이 LLM 경로 소스에 한 글자도 없는가 |

①에는 **47쌍 고정 단언**이 있다. 규칙을 더하거나 지우면 빨개진다 — 의도한 것인지
확인하고 숫자를 고쳐라.

③ 때문에 `render.ts`·`parse.ts`·`material.ts` 의 **주석에도** 해설 파일 이름이 없다.
읽을 수 있는 이름이 없으면 실을 길도 없다는 것이 이 봉인의 방식이다.

> 파이썬 원본 레포에 `tests/test_프롬프트_두층.py` 가 있었지만 이식되지 않아 한동안
> 그물이 없었다. 2026-08-14 에 위 셋으로 메웠다.

⚠️ 그래도 잡히지 않는 것이 있다 — **「태그는 양쪽에 있는데 뜻이 어긋난 것」.**
검사 자신이 그걸 단언으로 적어 두었다. 그건 두 파일을 나란히 놓고 사람이 읽어야 한다.

## 4. 언어 규칙 — 기준은 언어가 아니라 「나가는가」다

| 프롬프트 | 나가는 쪽의 언어 |
| --- | --- |
| `analysis` · `character` · `child` · `mission_reply` · `mission_summary` | **영어** |
| `judge_gave_away_element` · `judge_guided_toward_target` · `judge_invented_setting` | **한국어** |

**분석·캐릭터·아이가 영어인 이유는 토큰 절약이다.** 한글 한 글자가 영어보다 토큰을 더
먹는다. 지시문은 길고 매 턴 나가므로 여기서 아끼는 것이 크다.

**심판 셋이 한국어인 이유는 판정 대상이 한국어이기 때문이다.** 심판은 캐릭터가 만든
한국어 대사를 읽고 「경계를 넘었나」를 매기고, 판정 근거로 **대사에서 글자를 그대로
잘라 내야** 한다(`src/llm/judge.ts:429` 가 근거가 대사 안에 있는지 대조하고, 없으면 그
판정을 버린다). 판정 어휘 자체도 한국어다 — `{"판정": "위반"|"통과"|"판정불가", …}`.

### 예시 발화는 영어 프롬프트 안에서도 한국어다

판정 대상이 한국어 발화이므로 예시를 번역하면 예시가 아니게 된다. 실제로
`analysis/보낼것.md` 안에는 한글이 208자 들어 있고(`"다 같이 도와줘야 해요"` ·
`"며느리한테 화내지 말고 미안하다고 말해 주세요"` 같은 판정 예시와 `-니까` · `-어서`
같은 어미), `child/보낼것.md` 에도 「어… 그게…」·「몰라요」·`초1`·`초3` 이 그대로 있다.

`character/보낼것.md` 에는 한글이 0자다. 예시 발화를 안 쓰고, 대신 첫 줄이
`Write your ONE next line, in Korean.` 으로 출력 언어를 못박는다.

**즉 판단 기준은 「이 글자가 영어냐 한국어냐」가 아니라 「이 글자가 나가느냐」다.**
나가는 쪽이면 토큰을 아끼는 말로, 안 나가는 쪽이면 사람이 읽기 좋은 한국어로 쓴다.

## 5. 고칠 때 절차

### 캐시가 없다 — 고치면 바로 반영된다

`read()`(`src/llm/prompts/render.ts`)는 **부를 때마다 디스크를 읽는다.** 모듈
전역에 담아 두는 것이 없다(`tests/prompt-lab.test.ts` 가 그걸 검사한다).

⚠️ 그러니 **배포도 재시작도 필요 없고, 되돌릴 배포 경로도 없다.** md 를 저장하는 순간
다음 LLM 호출부터 새 글자가 나간다. 돌고 있는 회차 한가운데서 고치면 **같은 회차의
앞턴과 뒷턴이 다른 프롬프트로 돈다.**

### 그래서 이 차례로 고친다

1. **고치기 전에 골든셋 기준선을 찍는다.** (`/goldenset` 화면 · `src/llm/service/goldenset.ts`)
2. `보낼것.md` 를 고친다.
3. **다시 잰다.** 같은 정답지 파일로.
4. 점수가 떨어졌으면 되돌린다. 올랐으면 무엇을 고쳐서 올랐는지 `해설.md` 에 적는다.

### ⚠️ 지문이 바뀌면 이전 판과의 비교가 끊긴다

골든셋 한 판을 저장할 때 `analysis/보낼것.md` 의 sha256 을 `prompt_digest` 로 함께
박제한다(`promptDigest()` — `src/llm/service/goldenset.ts`, 칸은 `goldenset_runs`).

**나가는 파일만 잰다.** 그래서 `해설.md` 를 아무리 고쳐도 지문은 그대로다 —
**모델이 실제로 받은 글자가 바뀌었을 때만** 바뀐다는 뜻이다.

> 2026-08-14 전에는 파일 통째(한글 층 포함)를 쟀다. 🔴 그때 박제된 지문들은 지금
> 어느 파일과도 안 맞으니, 분리 전 판과 지문으로 잇지 마라.

> ✅ **지문이 OS 마다 갈리던 문제는 고쳤다** (2026-08-14).
>
> `fileDigest()` 는 **원문 바이트**의 sha256 이라 줄 끝의 `\r` 이 그대로 들어간다.
> 그전에는 같은 커밋인데 윈도우(CRLF)와 리눅스(LF)의 지문이 여섯 개 전부 달랐다.
> 레포 루트의 `.gitattributes` 가 줄바꿈을 LF 로 못박아 이제 **OS 무관하게 고정**이다.
>
> ⚠️ 정답지 `goldenset/*.jsonl` 도 같은 함수를 쓴다. 같이 고정됐다.

> `runs.prompt_version`(`src/llm/db/schema.ts`)은 프롬프트 내용과 아무 상관이 없다.
> 회차를 열 때 사람이 붙이는 이름표일 뿐이고, 자동으로 안 바뀐다. 이것으로 「어느
> 프롬프트였나」를 알 수 있다고 믿지 마라.

## 6. 실험판의 경계

작업대에서 고친 본문에는 세 가지 울타리가 있다.

### ① 회차 하나에만 걸린다

`experiment_prompts` 의 기본키가 `(run_id, name)` 이다(`src/llm/db/schema.ts:717-730`,
`sql/003_admin.sql:167-173`). 읽을 때도 `run_id` 로만 읽으므로
**다른 회차로 새지 않는다**(`readExperimentPrompts()` — `src/llm/repo/prompt-lab.ts:33-43`,
검사는 `tests/prompt-lab.test.ts:384-400`).

같은 (회차, 이름)에 다시 저장하면 행이 늘지 않고 본문만 바뀐다.

### ② `analysis` 와 `character` 둘만 실험할 수 있다

이 제약이 **세 곳에 박혀 있다.** 한 곳만 고치면 나머지 둘이 막는다.

| 어디 | 무엇 |
| --- | --- |
| 리포 (코드) | `실험할_수_있는_이름 = ['analysis', 'character']` — `src/llm/repo/prompt-lab.ts:24`, 어기면 `src/llm/repo/prompt-lab.ts:57-59` 에서 `ValueError` |
| DB (CHECK) | `experiment_prompts_name_check CHECK (name IN ('analysis','character'))` — `src/llm/db/schema.ts:728`, `sql/003_admin.sql:171` |
| 화면 | 같은 목록으로 `editable` 을 정한다 — `src/llm/service/prompt-lab.ts:102`, 폼 검증은 `src/app/(admin)/prompt-lab/actions.ts:41` |

`child` 나 `judge_*` 를 저장하려 하면 화면에서도 저장 층에서도 막힌다
(`tests/prompt-lab.test.ts`).

### ③ 나가는 본문 하나만 대체한다

실험 본문은 **`보낼것.md` 자리를 통째로 갈아끼울 뿐**이다. 재료를 만드는 코드도,
출력 스키마도, 판정 규칙도 그대로다.

사람이 쓴 글자가 그대로 나간다 — 오리지도 다듬지도 않고, 저장할 때도 손대지 않는다
(`src/llm/service/prompt-lab.ts`). ⛔ 빈 본문은 거절한다 — 빈 것을 저장하면 그 회차는
system 없이 도는데, 그게 실험인지 실수인지 나중에 못 가른다.

턴을 도는 길이 이 값을 집어 온다(`src/llm/service/step.ts` · `run.ts`). 부르는 쪽이
본문을 명시로 넘기면 그것이 이긴다 (「안 주면 파일」 규칙은 `chooseBody()` 한 곳에만
있다 — `src/llm/prompts/render.ts`).

## 7. 프롬프트가 아닌 것 — 여기서 찾지 마라

### 장면별 값은 DB 시드에 산다

「이 장면에서 `EMOTION` 을 인정하려면 발화에 무엇이 있어야 하나」, 「이 장면에서
캐릭터는 어떤 입장이고 무슨 걱정이 남았나」는 **md 가 아니라 `story_scenes` 표**에 있다.

| 칸 | 무엇 | 어디 |
| --- | --- | --- |
| `element_criteria` | 요소마다의 이 장면 인정 기준 | `src/llm/db/schema.ts:214`, 값은 `src/llm/db/seed.ts:294`·`:345`·`:378`·`:412` |
| `remaining_worries` | 이 장면에서 캐릭터에게 남은 걱정 (요소별 한 문장) | `src/llm/db/schema.ts:199`, 값은 `src/llm/db/seed.ts:278` 부터 |
| `scene_stance` | 이 장면에서의 캐릭터 입장 | `src/llm/db/schema.ts:193`, 값은 `src/llm/db/seed.ts:274` 부터 |
| `guidance_style` · `forbidden` | 어떻게 유도하나 · 무엇을 말하지 않나 | `characters` 표 — `src/llm/db/schema.ts:133` 근처 |

프롬프트는 **「그 값을 어떻게 쓰라」**만 적고, **값 자체는 시드가 갖는다.** 장면 하나의 판정이
이상하면 프롬프트가 아니라 시드를 먼저 보라.

⚠️ 캐릭터 프롬프트에 `scene_goal`(장면 학습 목표)은 **안 들어간다.** 읽으면 캐릭터가 아이
대신 그 문장을 말해 버린다. 안 넣는 것 셋은 `src/llm/engine/material.ts:235-251` 에 적혀 있다.

### 이 폴더 밖의 「프롬프트」들

이름이 프롬프트일 뿐, **이 규율 밖이다.** 두 파일도 태그도 작업대도 적용되지 않는다.

- `src/lib/recommendations.ts:160-162` 의 `SYSTEM_PROMPT` — 아이 앱의 동화 추천 큐레이터.
  아이 앱 도메인(Supabase)이고 대화 엔진과 DB 도 다르다.
- TTS 의 `stylePrompt` — 읽어 주는 말투 연기 지시. `src/tts/server.ts:109-113`,
  값은 `src/stories/fart-bride/data.ts` · `script.ts` 에 대사마다 붙어 있다.

## 8. 여덟 프롬프트 — 무엇이고, 어디까지 배선됐나

| 프롬프트 | 무엇 | 엔진에 붙었나 |
| --- | --- | --- |
| `analysis` | 아이 발화를 읽고 의도·핵심·사고 요소를 JSON 으로 뽑는다 | ⭕ `src/llm/engine/analyze.ts:243` |
| `character` | 캐릭터의 다음 대사 한 마디를 짓는다 | ⭕ `src/llm/engine/character.ts:58` |
| `child` | **아이 역할 대역** (측정 전용, 제품 아님) | 🔴 **아직 안 돈다** — 아래를 볼 것 |
| `judge_gave_away_element` | 캐릭터가 아이 대신 답을 말해 버렸나 | ⭕ `src/llm/judge.ts:443-461` |
| `judge_guided_toward_target` | 캐릭터가 이번 턴의 과녁 쪽으로 유도했나 | ⭕ `src/llm/judge.ts:477` |
| `judge_invented_setting` | 캐릭터가 없는 설정을 지어냈나 | ⭕ `src/llm/judge.ts:515` |
| `mission_reply` | 미션 턴의 아이대답요약·다리 대사 (이슈 #18) | ⭕ `src/llm/engine/mission.ts` — 미션 API(#19)가 아직 안 부른다 |
| `mission_summary` | 미션 종료 요약 (이슈 #18) | ⭕ `src/llm/engine/mission.ts` — 미션 API(#19)가 아직 안 부른다 |

심판 셋은 `boundaryChecks()`(`src/llm/judge.ts:572-590`)가 한 번에 부르고, 턴을 도는 길이
자동 채점을 켠 회차에서 그것을 부른다(`src/llm/service/turn.ts:609-614`).

### 🔴 `child` 는 정본이되 아직 안 돈다

**착각하기 쉬운 자리라 못박아 둔다.** 두 파일이 다 완성돼 있고, 검사도 통과하고,
작업대 화면에도 뜬다. **그런데 이 프롬프트로 LLM 을 부르는 코드가 `src/` 어디에도 없다.**

- `child_material` 이라는 글자가 `src/` 전체에 **0곳**이다.
- `src/llm/engine/` 에는 `analyze.ts` · `character.ts` · `material.ts` 셋뿐이고,
  아이 대역 엔진이 없다.
- `chooseBody('child', …)` 를 부르는 자리도 없다.

**그래서 회차를 돌려도 아이 대사는 이 프롬프트에서 나오지 않는다.** 지금 아이 발화는
사람이 넣거나 다른 경로에서 온다(`runs.default_utterance_source`).

**살려 둔다** (2026-08-14 사람 결정). 아이 역할 LLM 을 쓸 계획이 있고, 파일에 담긴 설계 —
특히 「일부러 **안** 주는 것」 표(`required_elements` · `element_criteria` ·
`guidance_target` · `remaining_worries` · `scene_goal` · 뒷이야기를 아이에게 안 준다) —
가 그때 다시 쓰인다. 정답을 알려 준 아이로 재면 「유도가 됐나」가 아니라 「아이가 정답을
봤나」를 재게 되기 때문이다. 지우면 그 판단이 같이 사라진다.

⚠️ `child` 는 **제품이 아니다.** 실제 서비스에서 아이는 사람이다. 이 프롬프트로 낸
「유도 성공률」은 사람 검수 전에 성과로 주장하지 말 것. 재는 것은 판 사이의 **차이**지
절댓값이 아니다.

## 9. 이 체제로 오면서 사라진 것

2026-08-14 에 한 파일 두 층 → 폴더 하나 두 파일로 옮겼다. **딸려 없어진 것 하나를
못박아 둔다** — 모르고 쓰면 조용히 안 먹는다.

### 실험 프롬프트의 낱개 자리표시자

그전에는 작업대에 써 넣은 실험 본문이 `{child_utterance}` · `{scene_description}` 같은
**낱개 이름**을 쓸 수 있었다. 재료 JSON 을 펴서 그 이름들로도 채워 주는 다리가 있었다
(`낱개()` — 스스로 「옛 프롬프트를 살려 두는 다리지 규격이 아니다」라고 적어 뒀다).

⛔ **그 다리는 없다.** 이제 자리표시자는 어디에도 안 채워지고 글자 그대로 나간다.
실험 본문은 **통째로 system** 이 되고, user 는 언제나 `materialJson(재료)` 다.

### 함께 사라진 코드

`sendableBody` · `materialTemplate` · `fill` · `placeholders` ·
`PlaceholderRemainingError` · `render` · `낱개` · `평평하게`.

`src/llm/prompts/parse.ts` 머리말이 각각 왜 없어졌는지 적어 두었다.
