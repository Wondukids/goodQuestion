# `src/post-activity` — 말하기 후 활동 도메인

이야기를 다 본 뒤 아이가 하는 활동이다. 장면 카드 넉 장을 순서대로 놓고, 그 카드와 **핵심
단어 12개**를 보면서 줄거리를 통째로 들려준다. 서버가 그 말을 받아쓴 다음 **12개 단어를
아이가 썼는지**를 가려 기록한다. 정본은 `docs/말하기후활동_명세.md`.

지금 이 폴더에 있는 것은 **단어 판정 하나**다 (이슈 #44 · 명세 6절).

## 이 도메인의 한 문장

**글자로 찾히는 것은 규칙이 끝내고, 남은 것만 LLM 이 한 번에 본다.** 그리고 LLM 이 댄 근거는
**아이 원문과 다시 대조해** 어긋나면 버린다.

```
①  규칙이 글자로 찾는다   → 찾히면  status='used',    decided_by='rule'   (LLM 안 부른다)
       │ 못 찾은 것만
       ▼
②  LLM 에게 묻는다        → 참이면  status='similar', decided_by='llm'
       │  「비슷한 말로 말했나」 하나만
       ▼
③  근거를 원문과 대조한다 → 원문에 없으면 그 판정을 버리고 status='missing'
```

🔴 **활동 한 건에 LLM 호출은 한 번뿐이다** (명세 6.3). 단어마다 부르지 않는다.

## 층

`src/report/README.md` 와 같은 규칙이다. 호출은 **위에서 아래로만** 흐른다.

| 층 | 폴더 | 하는 일 |
|---|---|---|
| engine | `engine/` | LLM 을 부르고(`judge.ts`) 재료를 만든다(`material.ts`) |
| domain | `domain/` | 순수 함수 — ①의 글자 찾기와 ③의 근거 대조. **DB 도 LLM 도 시각도 모른다** |

`types.ts` 는 층이 아니라 **부르는 쪽까지 함께 쓰는 계약 하나**다.

⛔ **repo 층이 없다.** 표 둘(`post_activity_results`·`post_activity_keywords`)에 넣는 것은
이슈 #45 의 몫이고, 이 도메인은 **넣을 값을 돌려줄 뿐**이다.

⚠️ 자리가 여기인 것은 **이 갈래가 정한 것**이다(명세에 없다 · 되돌려도 된다). 후활동은
리포트도 대화도 아니라서, `src/report/` 아래 두면 리포트 층 규칙에 얹히고 `src/llm/engine/`
에 두면 대화 턴 엔진과 섞인다.

## 🔴 이 도메인에서 사고가 나는 자리 셋

1. **두 글자 바닥** (결정 F14 · `domain/keywords.ts` 의 `후활동_조각_바닥`). 리포트의
   `낱말이_발화에_있나()` 는 「~다」로 끝나는 낱말의 어간을 떼어 찾는데, 두 글자 낱말은
   어간이 **한 글자**가 된다 — 「참다」→「참」. 한 글자는 「참새를 봤어요」에도 걸린다.
   ⛔ **`verify.ts` 를 고치지 않는다** — 그 함수는 리포트의 낱말 세기가 쓰고 있고 거기서는
   지금 동작이 맞다. **부르는 쪽인 여기서** 바닥을 건다.
2. **「비슷한 말」의 경계는 코드에 없다** (결정 F17 · 명세 6.4). 12줄 경계 표는
   `prompts/retelling_keywords/보낼것.md` 안에 산다. 판정이 흔들리면 **그 표를 고치지
   엔진을 고치지 않는다.** 이 폴더에 단어 이름이 한 글자도 없는 것이 그 약속의 모양이다.
3. **판정 실패는 오류가 아니다** (결정 F4·F8). 받아쓴 글은 판정보다 먼저 저장되고, 판정이
   실패하면 `analyzed: false` 로 200 이 나간다. 「판정을 못 했다」(`analyzed_at` NULL)와
   「단어를 하나도 안 썼다」(12행 전부 `missing`)는 **다른 말**이다 (명세 4.2).
