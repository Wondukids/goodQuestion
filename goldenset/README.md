## 2. 한 줄의 모양

```json
{"id": "gs_banggui_03_001", "검수": "초안", "scene_order": 3, "장면_이름": "대화1",
 "scene_description": "…", "conflict": "…",
 "previous_character_message": "ㅇㅇ아, 내 방귀가 너무 크다는 걸…",
 "child_utterance": "말해도 돼요. 가족이니까 이해해 줄 거예요.",
 "target_elements": ["PERSPECTIVE", "EMPATHY", "REASON", "SOLUTION"],
 "정답": {"child_intent": "OPINION", "detected_elements": ["PERSPECTIVE"],
          "utterance_validity": "VALID", "main_point": "…"},
 "메모": "왜 이렇게 매겼는지 · 애매하면 무엇이 애매한지"}
```

| 칸 | 무엇 |
|---|---|
| `id` | 파일 안에서 안 겹치는 이름. `gs_<이야기>_<scene_order>_<번호>` |
| `검수` | **`초안`** 또는 **`검수완료`**. 이 둘 말고는 못 쓴다 |
| `scene_order` · `장면_이름` | 어느 장면인지 |
| `scene_description` · `conflict` · `previous_character_message` · `child_utterance` · `target_elements` | **분석 프롬프트의 입력 5개 그대로**(`prompts/analysis.md:19-25`) |
| `정답` | 분석 LLM 이 내야 하는 4개 |
| `메모` | 사람이 읽는 칸. 채점에 안 쓴다 |

**맥락 칸 이름을 프롬프트 입력과 글자 그대로 맞춘 게 요점이다.**
골든셋 한 줄이 곧 프롬프트 입력이라, 옮겨 담다 어긋날 자리가 없다.

`//` 로 시작하는 줄과 빈 줄은 건너뛴다(파일 맨 위 경고문이 그래서 들어간다).

## 3. 돌리는 법

```bash
# 형식 검사 + 분포 요약 (LLM 안 부른다. 기본값)
uv run python -m goodquestion.goldenset

# 다른 파일
uv run python -m goodquestion.goldenset goldenset/banggui_검수전.jsonl

# 실제 분석 LLM 을 불러 채점한다 (돈이 든다)
uv run python -m goodquestion.goldenset --llm

# 검수 끝난 항목만
uv run python -m goodquestion.goldenset --llm --검수완료만

# ⭐ 돌리기 전에 — 호출 수와 예상 토큰만 본다 (API 0회)
uv run python -m goodquestion.goldenset --llm --검수완료만 --dry

# 앞에서 N 건만 (유료 모델에 상한을 건다)
uv run python -m goodquestion.goldenset --llm --검수완료만 --limit 10
```

⚠️ **유료 모델로 돌리기 전에는 `--dry` 를 먼저 본다.**
`--검수완료만` 을 빠뜨리면 30건이 아니라 **73건**이 돌아 2.4배가 나간다.
`--dry` 가 그 자리에서 「73건 · 초안 43건이 섞였다」를 찍는다.

> 📏 `--dry` 의 토큰 어림은 2026-08-12 실측이다 — `gemini-3.5-flash-lite` 30건에서
> 호출당 입력 6,178~6,194 · 출력 44~169 였다. **어림수이지 청구서가 아니다.**
> 입력의 97%가 매 호출 똑같은 시스템 프롬프트라 **비용은 거의 호출 수에만 비례한다.**
> 예상 금액은 `단가표.toml` 에 그 모델 단가가 있을 때만 뜨고, 없으면 **「모름」**이다.

형식이 틀리면 **`파일:줄번호` 와 함께** 터진다. 손으로 고치는 파일이라 이게 중요하다.


## 4. 채점 방법

| 값 | 어떻게 |
|---|---|
| `child_intent` | 정답과 같은가 → **정확도** |
| `utterance_validity` | 정답과 같은가 → **정확도** |
| `detected_elements` | 집합 비교 → **정밀도 · 재현율 · F1** |
| `main_point` | **안 잰다.** 자유 서술이라 사람 또는 LLM 심판 몫이다 |

- **정밀도** = 낸 요소 중 맞은 비율 (없는 걸 지어냈나)
- **재현율** = 정답 요소 중 찾아낸 비율 (있는 걸 놓쳤나)
- **micro 평균**이다. 항목별 비율을 평균하지 않고 전체 맞힘 ÷ 전체 예측으로 낸다.
  요소 1개짜리 항목이 4개짜리와 같은 무게를 갖지 않게 하려는 것이다.
- 분모가 0 이면 `0.0`. 낼 것도 맞힐 것도 없는 상태를 만점으로 쳐 주지 않는다.

## 5. 코드에서 쓰기

```python
from goodquestion.goldenset import 읽기, 돌린다, llm_분석기

항목들 = 읽기()
표 = 돌린다(항목들, llm_분석기)      # 분석기는 인자다 — 가짜를 주면 LLM 없이 돈다
print(표.child_intent_정확도, 표.요소_F1, 표.믿을_수_있나)
```

`돌린다()` 가 분석기를 **인자로 받는** 이유: 분석 호출부가 아직 이 레포에 없다
(터미널 실행기 트랙의 몫이다). `llm_분석기` 는 프롬프트를 읽어 `llm.complete` 를 부르는
**임시 어댑터**이고, 실행기가 생기면 그 코드로 갈아끼운다. 그때 채점기는 안 건드려도 된다.

## 7. 정답을 채울 때 (기획자 답이 온 뒤)

1. 후보 발화를 만들어 기획자에게 O/X 를 받는다 (`docs/설계/eval_계획.md` 5장 (3))
2. O 로 남은 발화에 라벨 초안을 붙여 이 파일에 넣는다. **이때는 `"검수": "초안"`**
3. 검수를 받아 고친 줄만 `"검수": "검수완료"` 로 바꾼다
4. `--검수완료만` 으로 돌린 점수만 보고서에 쓴다

**섞인 채로 낸 점수는 보고서에 쓰지 말 것.** CLI 가 초안이 섞이면 경고를 찍고
`채점표.믿을_수_있나` 가 `False` 가 된다. 이 구분이 흐려지면 `docs/설계/eval_계획.md` 7장이
경고한 "측정하고 있다는 착각"이 그대로 일어난다.

## 7-1. ⭐ 감정 문항 30건 — **다 채워졌다** (2026-08-12)

2026-08-11 에 **감정·공감 문항 30건**을 지었고, **8/11~12 인터뷰 여덟 라운드로
30건 전부에 사람이 정답을 매겼다.** `미채점/` 폴더는 비었고 지웠다.

| | 전 | 후 |
|---|---:|---:|
| 항목 수 | 43 | **73** |
| `검수완료` | 0 | **30** |
| `EMOTION` 정답 | 2 | **13** |
| `EMPATHY` 정답 | 3 | **16** |

**착수 때 `EMOTION` 정답이 2건뿐이라 감정을 못 쟀다.** 그게 이 30건을 지은 이유다.

⚠️ **`--검수완료만` 으로 돌려라.** 초안 43건은 옛 기준으로 매겨져 있어 섞으면
프롬프트가 나쁜 건지 정답지가 낡은 건지 구분이 안 된다(`TRACK-HANDOFF-corpus.md` 미결 2번).

### ⚠️ `main_point` 만 AI 초안이다

30건의 `child_intent` · `detected_elements` · `utterance_validity` 는 **사람이 하나씩 판정했다.**
**`main_point` 는 AI 가 썼다.** 「정답은 사람이 매긴다」 규칙에 형식상 걸리지만,
**`main_point` 는 `채점()` 이 아예 안 재는 칸이라**(4장) 점수에 영향이 0 이다.
그 근거로 2026-08-12 에 사람이 그렇게 하기로 정했다. **줄마다 `메모` 끝에 그 사실이 적혀 있다.**

### 🔴 판정하면서 나온 규칙 열둘

**문항보다 이게 값어치가 클 수 있다.** 문항 하나를 물을 때마다 잣대가 하나씩 딸려 나왔다.
**전문은 `notes/골든셋_정답매기기_진행.md` ①장.** 요지만 적으면 —

`PERSPECTIVE` 와 `EMPATHY` 는 한 발화에 함께 붙는다 · 마음과 안 붙은 상황 서술도
`PERSPECTIVE` 로 센다 · 단 이미 `REASON` 으로 센 구에는 거듭 안 붙인다 ·
표지 없는 까닭도 `REASON` 이다 · `EMPATHY` 의 상대는 며느리로 한정되지 않는다 ·
`-면` 이 방법을 제안하는 틀이면 `REASON` 이 아니다 · `REQUEST` **요소**는 대상이 발화에
적혀야 센다 · `intent` 와 `elements` 는 별개 축이라 요소가 빠져도 intent 는 그대로 둔다 ·
짧아도 마음을 짚으면 `VALID`, 사실 한 조각만 짧게 말하면 `SHORT` ·
감정 낱말 없이 표정·몸만 말한 것은 `EMPATHY` 가 아니라 `PERSPECTIVE` 까지다 ·
주어(「나는」) 유무로 판정을 가르지 않는다.

⚠️ **이 중 셋은 지금 `prompts/analysis.md` 문구와 어긋난다** — `-면` · `REQUEST` 대상 ·
감정 낱말 없는 `EMPATHY`. **프롬프트 반영 여부를 정해야 한다.**

### 🔴 호칭 — 아이가 캐릭터를 뭐라고 부르나 (2026-08-11 사람 결정)

**부르는 말**(캐릭터 얼굴 보고 부름)과 **가리키는 말**(제삼자 얘기를 함)은 다르다.
**가리키는 말은 역할명 그대로 써도 된다.** 문제는 부르는 말 쪽이었다.

| 상대 | 부르는 말 | 가리키는 말 |
|---|---|---|
| 며느리 (대화1·4) | **아줌마 · 언니 · 안 부름** | 며느리 ⭕ |
| 시아버지 (대화2) | **할아버지** | 시아버지 ⭕ |
| 마을 이장 (대화3) | **아저씨 · 이장님** | 이장님 ⭕ |

🔴 **정한 것은 「하나로 고정한다」가 아니라 「안 부르는 것을 기본으로 두고 나머지를 섞는다」다.**
아이마다 부르는 말이 다르고, 실제 아이 말에서 부름말 자체가 드물기 때문이다.
그래서 대화4의 `09_303` 은 「아줌마」, `09_304` 는 「언니」로 **일부러 다르게 뒀다.**

⚠️ **「며느리」와 「시아버지」는 아이 기준의 호칭이 아니다** — 둘 다 *서로에 대한* 관계를
가리키는 말이라 아이는 그 관계 밖에 있다. **「이장님」은 직책이라 누가 불러도 성립한다.**
다만 **금지는 아니다.** 이야기를 방금 들은 아이는 캐릭터를 그 이름표로 기억하고 있어
「며느리!」가 튀어나올 수 있다. **빼는 게 아니라 소수로 두는 것**이 실제에 가깝다.

⚠️ **아직 안 고친 곳** — 초안 43건의 대화1·4 에 「며느리」가 6건 남아 있다
(`03_002` `03_201` `03_204` `03_206` `03_208` `09_203`). 이 43건은 옛 기준으로 정답이
매겨져 있어 **미결 2번(정답 재검토)과 함께 손대는 것이 맞다.** 따로 고치지 마라.

### `찌른것` 은 어디로 갔나

`미채점/` 시절 각 줄에는 **`찌른것`**(무엇을 확인하려는 문장인가) 칸이 있었다.
로더가 모르는 칸이라 옮기면서 뺐고, **`메모` 맨 앞 `[찌른것: …]` 으로 옮겨 적었다.**

| 코드 | 무엇 | 왜 넣었나 |
|---|---|---|
| `평이` | 적대적이지 않은 보통 문장 | 기준점 |
| `감탄만` | 감정을 **감탄·행동으로만** (「야호! 나 해냈어!」) | 3차에서 못 잡았다 → 「센다」로 정해져 규칙이 넓어졌다 |
